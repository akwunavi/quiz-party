# ТЗ v2 (финал): Конструктор квизов — новый проект

Версия 2.0 · Все решения согласованы · После аппрува — код, этап 1.

---

## 0. Ключевые решения v2 (изменения против v1)

- **Новый репозиторий** и **новый проект Supabase**. Старый репо (`ivan_party`) остаётся нетронутым музеем ДР-пакета. Импорта старого пакета НЕТ — новая БД стартует пустой.
- **Кроссворд входит в v1 разработки** (не «потом»).
- Р7-математика уточнена: ставка бинарная **0 или 2**. Без ставки: +1/0. Со ставкой: +3/−2.
- Стек нового репо: **React + Vite + TypeScript**, тесты подсчёта баллов (Vitest), CI (GitHub Actions: типы + тесты + сборка перед деплоем в docs/ → GitHub Pages).
- Рейтинг вопросов (5 звёзд) переносится в новый проект.

## 1. Цель

Конструктор пакетов квиза: редактор создаёт пакеты, раунды с любыми механиками и вопросы всех типов через визуальные формы (`#/editor`), игра грузит выбранный пакет из БД. Без правки кода, с валидацией от человеческого фактора.

## 2. Ограничения и принципы

- Один (новый) репозиторий, GitHub Free + Supabase Free. REST-полинг 2 сек, без Realtime (RKN).
- Переносимость на свой домен/VPS без изменения архитектуры (статика + PostgreSQL; URL и пути медиа — через конфиг).
- UX игроков и проектора наследуется из текущего проекта (RoundShell, анимации, drag&drop, очередь ответов с retry, FinaleScreen, ErrorBoundary — переносятся).
- Экран/анимации привязаны к механике, не к раунду.

## 3. Модель данных (Supabase, новый проект)

```sql
create table packs (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  status text not null default 'draft',   -- draft | ready | active | played | archived
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table pack_rounds (
  id uuid primary key default gen_random_uuid(),
  pack_id uuid references packs(id) on delete cascade,
  position int not null,
  mechanic text not null,
  title_lines jsonb not null default '[]',
  rules jsonb not null default '[]',
  rules_audio text,
  timer_seconds int not null default 60,
  settings jsonb not null default '{}',
  off_scoreboard bool default false,
  answers_reveal text default 'after_question', -- after_question | after_round | never
  status text default 'draft'
);

create table pack_questions (
  id uuid primary key default gen_random_uuid(),
  round_id uuid references pack_rounds(id) on delete cascade,
  position int not null,
  question_text text default '',
  media jsonb default '{}',       -- { question: [], voice: null, answer: [], hidden: false }
  answer jsonb default '{}',
  answer_note text,
  service jsonb default '{}',     -- word1/word2 ребусов, пометки
  is_final_question bool default false,
  status text default 'draft',
  hidden bool default false       -- мягкое удаление
);

create table edit_log (
  id bigint generated always as identity primary key,
  editor text not null,
  entity text not null, entity_id uuid not null,
  action text not null,
  diff jsonb,
  at timestamptz default now()
);
-- + teams, game_state(pack_id), answers, question_ratings — как в текущем проекте
```

Статусы пакета: draft → ready (валидатор пройден) → active (игра: структура заблокирована, тексты можно) → played (правки только через «Создать копию») → archived.

## 4. Типы вопросов (answer.mode)

Тип ответа — свойство вопроса; content_type вычисляется из наличия медиа автоматически.

| mode | структура answer | автопроверка |
|---|---|---|
| `free_text` | correct ("Начало / Inception"), display | fuzzy (Левенштейн, варианты через `/`) |
| `choice` | choices[{key,text}], correct_choice, display | точная буква (гомоглифы) |
| `order` | choices, correct_order "ГБАВ", display | точное, всё-или-ничего |
| `match` | left, right, correct_pairs ["1А",...], display | точное, всё-или-ничего |
| `crossword_word` | слово + позиция в сетке | по буквам, регистр/ё не важны |
| `none` | display | только ручная |

- Частичных баллов нет. Поверх любой автопроверки — финальное слово админа (✓/✗ в AdminAnswersView).
- Нормализация везде: регистр, ё=е, пунктуация (как сейчас в answerCheck).
- Match: любые комбинации контента (картинки↔текст, треки-по-номерам↔исполнители), у игрока drag&drop.

## 5. Реестр механик (плагины)

Механика = модуль: экран проектора + форма игрока + подсчёт + форма редактора + декларация настроек. Новая механика = новый модуль + строка в реестре; БД не меняется (settings/payload — jsonb).

| ключ | прототип | ключевые settings |
|---|---|---|
| `standard` | Р0/Р1/Р6-вопросы | autoAdvance(+DelayMs), useTts, pointsPerQuestion; Р0 = standard + off_scoreboard |
| `test_stop` | Р3 | stopOnWrong: стоп после первой ошибки, пропуск ≠ ошибка |
| `rebus` | Р2 | 2 картинки, word1/word2 обязательны, автовалидация «3 последние + 3 первые» |
| `jeopardy` | Р4 | themes[{name, tiles[{value, audio, correct}]}], форма-таблица |
| `stakes_unique` | Р5 | stakesValues [0..5], каждая один раз |
| `stakes_free` | Р7 | stakesValues **[0, 2]**; верно со ставкой +3, неверно со ставкой −2, без ставки 1/0 |
| `thematic_x2` | Р6 | последний вопрос = тема, удвоение ручной кнопкой |
| `crossword` | новый | см. п.6 |

Порядок раундов свободный (position, стрелки/drag&drop), нумерация на проекторе из позиции, число раундов произвольное, разогрев опционален. metaLine — автогенерация из настроек с ручным переопределением. answers_reveal per-раунд: сразу / в конце раунда / никогда.

## 6. Механика «Кроссворд»

**Контент:** 6–10 слов с определениями.

**Автогенерация сетки:** алгоритм перебирает большое число раскладок (перестановки порядка слов × позиции), максимизирует пересечения и компактность, выдаёт классическую сетку с нумерацией «по горизонтали / по вертикали». Если слово не легло (нет общих букв) — редактор сразу сообщает: «не уложилось: СЛОВО — замени», проблема решается при подготовке пакета, не на игре. Кнопка «Перегенерировать» (другой вариант раскладки). Сетка фиксируется в settings раунда после генерации.

**Игровой флоу:** раунд стандартный, вопрос-за-вопросом; таймер одинаковый на каждое слово (30 или 60 сек — настройка раунда). Проектор: сетка показывается один раз после правил, затем обычный вид вопросов (определение текущего слова). Телефон: сетка постоянно на экране с начала раунда, текущее слово (синхронно с проектором) подсвечено.

**Ввод игрока:** тап по строке → стандартная клавиатура → слово целиком подставляется в клетки. Длиннее клеток — обрезаем, короче — пустые клетки видны. Валидации ввода нет.

**Пересечения (вариант «б»):** ответы хранятся по-словно, не по-клеточно. Конфликт буквы в общей клетке не блокирует и не перезаписывает чужое слово; проверка — по словам. Сетка у игрока — визуализация его собственных ответов.

**Баллы:** 1 балл за каждое верное слово (по буквам, регистр/ё/пунктуация не важны). Финальное слово админа — как везде.

## 7. Медиа (Supabase Storage)

Bucket `quiz-media`, `pack-<id>/...`, drag&drop из форм. Три слота вопроса: медиа вопроса (до 4), озвучка (voice mp3, готовится отдельно), медиа ответа; + rules_audio раунда; + флаг hidden (видео-как-аудио). Сжатие картинок в браузере при загрузке (до 1920px, JPEG ~85%). Аудио/видео не трогаем. Тяжёлые видео допустимо класть в репо. Валидатор проверяет существование файлов.

## 8. Редактор `#/editor`

**Auth:** Supabase Auth. Роли: **owner** (Иван — всё) / **editor** (создание/правка, удалений нет — только «скрыть», active-пакет не трогает). RLS на уровне БД. Все правки — в edit_log.

**Экраны:** Список пакетов (карточки, статус, % готовности, дублировать, + новый) → Пакет (раунды, порядок, экран готовности со списком проблем) → Раунд (настройки + список вопросов) → Вопрос (форма по mode, 3 медиа-слота, answer_note, статус, превью: проектор/телефон/админка).

**Валидатор** (черновик→готов): текст+ответ заполнены; choice ≥2 вариантов и correct_choice; match полные пары; order полный; медиа-ссылки живые; ребус: правило 3+3 сходится; кроссворд: все слова уложены; metaLine соответствует факту.

**Правки на лету:** в active — только тексты. **Адаптив:** правки текстов с телефона; полная сборка — desktop.

## 8а. CJM редактора (по шагам)

**Вход:** `/#/editor` → email+пароль → список пакетов.

**Список пакетов:** карточки (название, бейдж статуса, полоса готовности, дата), «+ Новый пакет», меню карточки: Открыть · Дублировать · Архивировать (архив/удаление — только owner).

**Новый пакет:** модалка «Название» → создать → экран пакета.

**Экран пакета:** переименование кликом; список раундов строками (позиция · название · механика · прогресс вопросов · статус), стрелки ↑↓ для порядка; «+ Добавить раунд»; кнопка «Проверить готовность» → панель проблем, каждая кликабельна и ведёт к месту.

**Добавить раунд:** модалка: выпадашка механики из реестра + название → экран раунда.

**Экран раунда:** настройки (заголовок проектора, таймер, правила списком, озвучка правил, показ ответов, «вне зачёта», блок настроек механики, metaLine автотекстом с ручным переопределением) + список вопросов + «+ Вопрос».

**Форма вопроса (3 зоны, на телефоне вертикально):**
1. Контент: текст вопроса; три зоны загрузки (медиа вопроса до 4 файлов, галка «только звук» у видео; озвучка mp3; медиа ответа); answer_note. Сжатие картинок автоматически.
2. Ответ: переключатель типа (свободный/варианты/порядок/сопоставление/без автопроверки), форма меняется:
   - свободный: correct (варианты через «/») + display;
   - варианты: строки А-Г, радиокнопка «верный» (валидатор не выпустит без неё);
   - порядок: правильная последовательность собирается перетаскиванием вариантов, строка типа «ГБАВ» формируется сама;
   - сопоставление: две колонки, связи рисуются тапами (1→Б), correct_pairs собирается сам.
3. Превью: вкладки Проектор / Телефон / Админка, живой рендер.

Низ формы: статус Черновик/Готов (переключение на «Готов» гоняет валидацию с подсветкой), автосохранение + кнопка «Сохранить», «← к раунду».

**Особые формы:** ребус — картинка+слово ×2, живая проверка правила 3+3 («не сходится: получается X, написано Y»); jeopardy — таблица тем × ячейки (цена, mp3, ответ); кроссворд — таблица «Слово|Определение» (6–10), «Собрать сетку» → рендер сетки с нумерацией, красная подсветка неуложенных слов, «Перегенерировать», «Зафиксировать».

**Навигация:** хлебные крошки «Пакеты → Пакет → Раунд → Вопрос». Готовый пакет выбирается в выпадашке на экране хоста → «Начать игру».

## 8б. Темы оформления

Реестр тем в коде (по образцу механик); у пакета — настройка «Тема», применяется ко всем экранам (проектор, телефон, финал).

- **v1: «Классика»** (текущий тёмный стиль) и **«Новый год»** (синие тона, падающий снег фоном, снежные шапки на заголовках, вьюга-градиент на титулах, снежинки в финале).
- Тема = декоративный слой (ThemeLayer): палитра + фоновые анимации + украшения заголовков. Не трогает логику/таймеры/полинг.
- Производительность: частицы автоотключаются на слабых телефонах (снег гарантированно на проекторе); проверяется на тестах.
- Тестирование: превью в редакторе рендерится в теме пакета; в dev-режиме — прогон темы (титул → вопрос → финал).
- Новые темы позже = новый модуль в реестре, без изменений БД.

Шарёбельная ссылка игрокам: `#/player?pack=N` + QR-код в лобби (этап 2).

## 9. Интеграция с игрой

HostScreen: выпадашка «Выбрать пакет» (ready/played; draft — с предупреждением) → старт пишет pack_id в game_state. Загрузчик тянет пакет один раз, кеширует (память + localStorage). Формат конфига совместим с текущим RoundShell. TOTAL_ROUNDS/DISABLED_ROUNDS — вычисляются из пакета.

## 11. Этапы работ

1. Новый репо + каркас (Vite+TS+CI) + новый Supabase: миграции, RLS, Auth, роли.
2. Перенос игрового ядра из старого проекта (RoundShell, PlayerPage, AdminPage, очередь, полинг) на TS + загрузчик пакетов из БД + выбор пакета на HostScreen.
3. Редактор: пакеты и раунды (статусы, порядок, настройки механик, готовность).
4. Редактор: вопросы (все mode, медиа со сжатием, превью) + валидатор + edit_log.
5. Механика «Кроссворд»: генератор сетки, формы редактора, экраны проектора/игрока, подсчёт.
5а. Темы оформления: ThemeLayer, «Классика» + «Новый год», превью в редакторе, перф-тест на телефонах.
6. Дополнения п.10 (экспорт PDF, индикаторы связи, heartbeat, рейтинг).
7. Обкатка на тестовом пакете (devSeed переносится), фиксы, приёмка.

Каждый этап = рабочий деплой.

**Не входит:** частичные баллы, оффлайн-режим, банк вопросов, импорт старого пакета, кастомизация оформления отдельно от механики.
