# Решения и предложения

| Вопрос | Статус | Основание |
|---|---|---|
| Использовать существующий исходный RUN №3 как отправную точку | Техническая рекомендация, требует пользовательской приёмки внешности | Оригинал и исправленный alpha-v2 доступны, бег устойчив с исходного #36. |
| Две стойки: FRONT_STAND и RACE_STAND | Рабочее архитектурное решение для дальнейшего планирования, не разрешение на генерацию | Первые кадры IDLE/SELECTED/RUN совпадают визуально; #0 IDLE закреплён как FRONT_STAND. RUN заметно боковее, поэтому событиям нужна своя боковая стойка. |
| RUN loop v2 #25–36 | Рабочая рекомендация, художественно не утверждён | Два 12-кратных MP4 уже собраны; основной цикл предпочтительнее, но небольшой скачок головы/лап остаётся. См. VISUAL_ACCEPTANCE.md. |
| Alpha v2 вместо присланного alpha-v1 для будущих тестов | Техническая рекомендация | Присланный `dog3-run-alpha.webm` побайтно совпал с историческим v1; отчёт v2 описывает удаление штатива/пола и восстановление глаза. Обе версии сохранены. |
| FRONT_STAND = IDLE #0 | Рабочий опорный кадр, требует пользовательской визуальной приёмки | RGB #0 всех трёх MP4 почти совпадает, поза устойчивая и обращена к зрителю вправо. Исходный фон пока присутствует. |
| IDLE full / short loop | Полный клип не зацикливать; #34–58 — технический кандидат | #120→#0 заметно меняет морду/глаза; #58→#34 существенно ближе. См. ASSET_ACCEPTANCE.md. |
| SELECTED | Использовать как одноразовую реакцию, не луп | Финал #120 улыбается, но не возвращается к FRONT_STAND #0; выход к первому START нужно проверить отдельно. |
| Переиспользование STOP как FINISH | Проверить после создания STOP | Для №4 сработало в игровом масштабе; совместимость №3 нельзя предполагать. |
| Общий alpha pipeline Bulldog №1 | Использовать без изменений после появления новых клипов | `bulldog1-frenk/alpha_pipeline/README.md` описывает BiRefNet, temporal agreement, matting и проверку Chromium. |

Решения о новых генерациях, визуале и интеграции в V3 остаются за пользователем. Имена `v2` и `candidate` не являются доказательством утверждения.

Приёмка дополнительно присланных файлов документирована в ASSET_ACCEPTANCE.md и MANIFEST.json. Идентичность повторного RUN и alpha-v1 установлена SHA-256, не по имени.
