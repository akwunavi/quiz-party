# Рокки — блокер полной цепочки RUN → STOP → STAND → START → RUN

**Статус:** пользователь утвердил оба игровых движения, STOP и RACE_START. Их файлы и кадры не изменены. Полная игровая лаборатория и финишный сценарий не выпускались: вход в утверждённый STOP расходится с фазой RUN, которую реально выдаёт неизменённая Race V3 перед остановкой.

## Точная причина

- В утверждённой лаборатории RACE_START (`../race-start-v3-lab/`) визуальная ячейка RUN №22 содержит исходный RUN **#62**. После START показываются #52–62, затем повторяется утверждённая петля #61–72 с начальной фазой #63. Это уже визуально принятая игровая версия.
- `alignedStopTime` и `nextStopTime` неизменённой модели V3 выравнивают начало STOP/FINISH по `RUN_JOIN=23/24` с шагом `LOOP=12/24`. Во всех проверенных событиях пресетов A/B/C последняя показанная ячейка RUN перед STOP — **№22**, независимо от мирового темпа. То же верно перед `FINISH_DECELERATE`.
- Утверждённый STOP (`../stop-v3-lab/`) был визуально проверен после исходного RUN **#68**: диагностический RUN там длился 31/24 с и последней была ячейка №18, содержащая #68. STOP начинается с Kling STOP #18 со своей уже принятой локальной компенсацией −38/+17 px.

MP4 фиксирует мировую позицию только ради сравнения формы на шве; это не полноценная физическая гонка и не попытка скрыть конфликт. Видео: H.264, `yuv420p`, 1920×1080, 24 FPS, 2,25 с, `faststart`.

## Влияние на задачу

Повторно использовать RACE_START после RACE_STAND **по позе возможно**: принятый вход RACE_STAND → START уже проверен, а STOP → RACE_STAND — в принятой STOP-лаборатории. Блокер находится раньше: в реальной точке V3 **RUN #62 → STOP #18**. Поэтому полная последовательность не может быть представлена как естественная без изменения утверждённой визуальной фазировки RUN или STOP либо времени физической остановки.

Пять категорий скорости не получили полноценную игровую проверку цепочки: фазу №22 задаёт модель независимо от множителя скорости, но выдавать лабораторию с явным скачком как рабочую нельзя. Система результатов, scoring и мировая траектория не менялись.

Отдельный FINISH на существующем STOP пока **тоже заблокирован**: `nextStopTime` выравнивает его к той же RUN-ячейке №22 → исходному #62. Поэтому MP4 финиша как пригодной сборки не создавался.

## Варианты для отдельного решения пользователя

1. **Проверить индивидуальную визуальную фазировку RUN перед STOP/FINISH.** Использовать только существующие кадры утверждённого цикла и сохранить физические времена/позиции V3; нужно найти способ подойти к #68 без заметного скачка или искажения частоты бега. Это затронет порядок/тайминг показа принятого RUN и потребует новой визуальной приёмки всей границы START→RUN→STOP. Результат не гарантирован.
2. **Подготовить отдельный вход торможения из фазы #62.** Утверждённый STOP #18–72 при этом остался бы нетронутым, но потребовалось бы новое движение-мостик и отдельное согласование его производства.
3. Изменить физическое время STOP на 6 кадров для совпадения с #68. Это затронет Race V3 и результаты; **не рекомендуется** и не выполнялось.

Новых Kling-генераций, alpha-обработки, изменений STOP/RACE_START/RUN/RACE_STAND, других собак, production, merge и deploy не было.
