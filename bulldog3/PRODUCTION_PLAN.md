# Минимальный план полной библиотеки №3

## Архитектура стоек

**Рекомендация: вариант B, две стойки**, с уточнением референсов после согласования. Ранний RUN source даёт стойку лицом/три четверти вправо, пригодную как *кандидат референса* для выбора, а стабильный бег смотрит вправо более сбоку. Если использовать только раннюю стойку для событий и финиша, каждое действие потребует дополнительного поворота и создаст риск того же скачка ракурса, который уже проявился у №4.

- `FRONT_STAND` — выбор/презентация. Точный кадр и необходимость отдельного IDLE утверждаются после получения MASTER; ранний source #0–23 может быть только референсом, пока фон не удалён.
- `RACE_STAND` — общая устойчивая боковая стойка на четырёх лапах для STOP, действий, RACE_START и FINISH. **В доступном RUN её нет.** Нужен согласованный референс без искусственного растяжения частей тела.
- `INITIAL_START` должен физически перевести фронтальный ракурс в правый RUN либо завершиться в RACE_STAND и перейти через RACE_START. `RACE_START` после действий может быть отдельным клипом; вопрос решать по концам реально полученных движений.

## Последовательность с контрольными воротами

1. Получить оригинальный MASTER №3, если он существует, плюс любые исходные IDLE/SELECTED и отклонённые версии. Утвердить шерсть, морду, уши, масштаб, ракурс и выбранный участок RUN как цветовой эталон. Если MASTER нет, согласовать RUN source как заменяющий референс внешности.
2. Диагностические повторы alpha-v2 #25–36 и #12–23 готовы; см. [VISUAL_ACCEPTANCE.md](VISUAL_ACCEPTANCE.md). Рабочая рекомендация — #25–36. Дождаться художественного утверждения внешности и петли пользователем. RUN уже существует; новый Kling RUN нужен только при обнаружении нерешаемой проблемы исходника.
3. Утвердить `FRONT_STAND` и создать/подтвердить `RACE_STAND`. До этого не тратить кредиты на события.
4. Спроектировать первоначальный START из FRONT_STAND в RUN и STOP из проверенной фазы RUN в RACE_STAND. Проверить оба в движении; для restart определить, нужен ли отдельный RACE_START.
5. Подготовить IDLE/SELECTED для выбора; порядок относительно START можно менять по зависимости референсов, но не утверждать SELECTED без совместимого выхода к старту.
6. BUTTERFLY: только собака, программная бабочка отдельно. Сохранить вход/выход в RACE_STAND.
7. SNIFF_PEE: нюхание и поднятие задней лапы без потери языка/контура; после фактического финального кадра решить, нужен ли RETURN. Не вырезать середину шага ради стыка.
8. ROLL: физическая хореография стойка→бок→спина→покачивание с движением лап→бок→естественное вставание→та же RACE_STAND. Проверить анатомию и линию земли покадрово.
9. FINISH: сначала протестировать существующий STOP как торможение с удержанием стойки, затем решать, нужна ли новая генерация.
10. Пропускать новые клипы через **существующий** `bulldog1-frenk/alpha_pipeline/`, сохраняя исходники, маски, параметры и QA на четырёх фонах. Только после визуальной приёмки всей цепочки подключать №3 к изолированной V3; production — отдельное решение.

Если петля, стойки и выходы событий окажутся совместимыми, ориентировочный минимум платных новых клипов: IDLE, SELECTED, INITIAL_START, STOP, RACE_START, BUTTERFLY, SNIFF_PEE и ROLL — **до восьми**, плюс поза RACE_STAND. RETURN и отдельный FINISH добавляются только при доказанной необходимости. Это зависимый план, не заказ генераций и не обещание точного числа: некоторые состояния могут оказаться уже существующими у пользователя или совместимыми без отдельного клипа.
