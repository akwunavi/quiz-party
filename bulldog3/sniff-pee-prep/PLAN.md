# Рокки №3 — SNIFF_PEE: пакет для одной будущей генерации

**Статус:** подготовка на согласование, 16.10.2026. Генерация, alpha, монтаж и игровая лаборатория не запускались. Исходные анимации и модель Race V3 не изменялись.

## Фактические ориентиры

- **Bulldog №4 — основной принятый пример.** Пользователь утвердил движение нового Kling `kling_20261009_VIDEO_Animate_th_144_0.mp4`: 241 кадр, 24 FPS, 10,0417 с. Исходное движение: стойка #0–12; наклон примерно #15–18; нос у земли примерно #36–132; подъём задней лапы #132–144, удержание до ~#204, язык ~#156–180; опускание лапы около #208; поза после действия #216–234, но #240 ещё содержит шаг. Поэтому для №4 понадобился **отдельный RETURN**, а не прямой переход к START. Принятая V3 использует оптимизированный SNIFF_PEE 7,2604 с + RETURN 2,7208 с. См. `docs/bulldog-race/DECISIONS.md`, `docs/bulldog-race/DOG4_ASSETS.md`, `DOG4_V3_ALL_EVENTS_REPORT.md`. Точный текст **отправленного** в Kling промпта №4 в архиве отсутствует (`docs/bulldog-race/PROMPT_ARCHIVE.md`); приписывать ему новый текст нельзя.
- **Фрэнк №1 — учтённые ошибки, не основной образец приёмки.** Его фактически отправленные промпты есть в ветке `claude-frenk-to-codex` (`bulldog1-frenk/sniff_v1/prompt_sent.txt`, `sniff_v2/prompt_sent.txt`). V1 отвергнут пользователем: ~3,3 с «клевания» головой, поднятая назад вместо вбок задняя лапа, морфинг лапы, посторонняя точка у носа. В V2 ушло клевание, но лапа снова шла назад. Поздняя V3.2 — монтажный технический кандидат 8,33 с, в его отчёте прямо указано, что **визуальную приёмку он не прошёл**. Утверждённого финального SNIFF_PEE Фрэнка в проверенных материалах нет. Этот prompt адаптирует конкретные анатомические указания реально отправленного V1 и исправляет наблюдавшиеся ошибки, а ритм и необходимость возврата берёт из №4. Он **не является копией не найденного промпта №4**.

## Задание на генерацию

- Отправить [KLING_PROMPT.txt](KLING_PROMPT.txt) и **оба** PNG; одна сцена, `image_to_video`, `kling-video-v3_0`, 10 с, 720p, звук и multi-shot выключены, если модель поддерживает эти параметры. Ожидаемый по предыдущим исходникам MP4 — 1276×720, 24 FPS, около 241 кадра; фактические метаданные проверить после получения.
- **Ориентир затрат — около 60 кредитов**: подтверждённые генерации Фрэнка на той же модели/разрешении стоили 30 за 5 с и 48 за 8 с, то есть исторически 6 кредитов/с. Для утверждённого исходника №4 и текущего тарифа стоимость не подтверждена. Claude должен проверить показываемую Kling цену/лимит **до** отправки и при расхождении сообщить пользователю. Эта подготовка не разрешает запуск.
- 10 с выбраны потому, что принятая схема №4 занимает суммарно 9,98125 с неподвижных визуальных фаз SNIFF_PEE+RETURN; короткие 5–6 с не вместят естественный нюх, подъём и возврат без заметного ускорения. Промпт просит действие приблизительно в первые семь секунд и возврат в последние три, но Kling может не соблюдать указанные доли. Точные точки монтажа определять только по готовым кадрам.

## Race V3: как использовать **один** клип без изменения физики

Из `dog4-v3-lab/model.mjs`: после STOP физика создаёт отдельные неподвижные сегменты `SNIFF_PEE` **7,2604167 с** и `RETURN` **2,7208333 с**, вместе **9,98125 с**; затем утверждённый START **1 с**. Физический таймлайн уже включает RETURN даже если Рокки вернётся в стойку внутри одного Kling-клипа. Нельзя удалить RETURN из модели без изменения результатов. В будущем один цельный исходник следует **визуально** разделить на две части: SNIFF_PEE до выбранного непрерывного кадра, RETURN с этого следующего кадра до достигнутой RACE_STAND. Обе части остаются одной последовательностью кадров; событие и мировая координата не меняются. Если стойка достигнута раньше конца RETURN, показывать утверждённую RACE_STAND до старта. Если позже конца суммарных 9,98125 с, оценить минимальный монтаж по реальному движению и вынести проблему на согласование; не обрезать шаг и не ускорять жесты автоматически. Возможна незначительная разница 10-секундного Kling и окна V3 — её точное решение зависит от числа полезных кадров.

Будущая цепочка: утверждённый RUN (принятая визуальная фаза) → STOP 37 кадров → RACE_STAND → новый единый клип, визуально распределённый по SNIFF_PEE+RETURN → RACE_STAND → RACE_START 24 кадра → RUN. Для alpha применять существующий `bulldog1-frenk/alpha_pipeline/dog_alpha.py`, затем отдельно проверять уши, морду, три опорные лапы, поднятую заднюю лапу и просветы между ногами на белом, чёрном, зелёном и бежевом фоне. Только после визуального утверждения исходного движения готовить маски, атлас, отдельную лабораторию и игровой MP4 во всех пяти категориях скорости. Ничего из этого сейчас не выполнено.

## Риски и критерии визуальной приёмки исходника

1. **Анатомия при метке:** у Фрэнка лапа уходила назад и превращалась в тёмный размытый выступ; проверить именно боковой подъём из тазобедренного сустава, согнутое колено, три устойчивые опоры, отсутствие лишней лапы и превращения передней в заднюю. Нужен полный просмотр, включая игровые ~207×116 px, поскольку видимость жеста меняется при уменьшении.
2. **Нюх:** V1 Фрэнка 3,3 с повторно «клевал» мордой пол. Проверить небольшое осмысленное движение носа, без ритмичного качания всей головы. В V2 это улучшилось, но лапа осталась неправильной.
3. **Конечная стойка:** №4 после действия не вернулся к исходной стойке сам, поэтому потребовался RETURN с переступанием. Для Рокки сравнить конец не только по силуэту: морду, глаза, уши, цвет, каждую лапу, ракурс, масштаб и линию земли с обоими PNG. Совпадение входных first/last image не гарантирует выход.
4. **Ритм:** №4 сохраняет язык и повтор лапы по пользовательскому утверждению, но для Рокки заказано одно цельное действие без лишних жестов. Не вырезать середину шага ради окна. Стабильный конец может заполнить остаток RETURN стойкой.
5. **Посторонние пиксели:** у Фрэнка возникал объект у носа, у №4 были проблемы alpha вокруг светлой части глаза. Проверять наличие объектов и исходной тени до обещания чистой alpha; маттинг не должен отрезать тёмную шерсть Рокки вместе с фоном.

**Следующий шаг:** пользователь согласует этот пакет; Claude проверяет актуальную цену и выполняет одну генерацию. Затем Рокки проходит отдельную визуальную приёмку до alpha и игровой сборки.
