# Bulldog Racing — вторая проверка лаборатории раунда (09.11.2026)

Ветка `claude/bulldog-round-lab-20261109`. Не менялись: утверждённые анимации, физика Race V3 (кроме опциональной опции длительности — см. п. 2), production, `docs/`. Kling не запускался, новых материалов для пьедестала нет, зимняя арена не делалась. Все проверки — по метрикам, кадрам и деталь-роликам; «на глаз в реальном времени» оценивать вам.

## 1. Почему собаки «неслись»
Измерено (`tools/speed_cadence.mjs`, `reports/cadence_and_speed.txt`, сид 1):
* **Частота лап не ускорена.** При скорости показа ×1 ячейки RUN сменяются 23,92–23,97 раз в секунду у всех пяти собак (утверждённые 24 к/с; у Рокки пропуски фазировки не меняют темп смены ячеек). Лаборатория сама сверх контрактов не ускоряет.
* **Главная причина — мой демонстрационный ролик.** `ROUND_FULL.mp4`/`DEMO_3` я записал с переключателем «скорость ×2» (чтобы уложиться по длине) и с D=30. ×2 удваивает ВСЁ время: лапы шли 48 кадров/с вместо 24, а скорость по трассе — вдвое выше. Это ошибка записи ролика, не движка. Кроме того, запись экрана Playwright шла 25 к/с против 24 к/с анимации (биения), а при низкой частоте рендера шаги были крупнее кадра. Новые ролики снимаются детерминированно (шаг 1/30 с, кадры из canvas) — идут строго в реальном времени.
* **Структурная причина (не ошибка): частота лап и скорость по трассе — разные вещи.** Лапы 24 к/с (цикл 0,5 с, 2 цикла/с). По трассе при D=42 собаки идут 25–31 px/с на экране 1920 (≈1,3–1,6% ширины экрана в секунду), т.е. за один цикл лап собака смещается на 12–16 px при длине тела ≈108 px (0,11–0,14 длины тела на цикл); при D=30 — 17–22 px (0,16–0,2), при D=60 — 9–11 px (0,08–0,1). Лапы «крутятся» заметно чаще, чем собака продвигается — это и даёт ощущение «несётся на месте»; пустой нейтральный фон не даёт точки отсчёта скорости. Чем больше D, тем сильнее этот перекос (собаки медленнее при той же частоте лап). **Какое именно отношение «правильно» — не измерялось** (эталонной шаговой длины в клипах нет: RUN снят «на месте»), это решает ваш глаз.
* Масштаб спрайтов не менялся (207×116 при 1920): на ощущение скорости влияет только через крупность, отдельный ролик F показывает крупный план ×2.
* Что даст арена: параллакс и разметка земли меняют воспринимаемую скорость ПЕРЕМЕЩЕНИЯ, но не частоту лап. Ролики E/F (следящая камера, земля с разметкой) — это модель такого эффекта, не обещание результата.
* Исправление в лаборатории: при скорости ≠ ×1 в гонке выводится красная плашка «ЛАБОРАТОРНОЕ УСКОРЕНИЕ». Физику, D, места и RUN-клипы я не менял.
* Ролики (все — реальное время, сид 1, 12 с): `SPEED_1_duration_and_playback_speed.mp4` — A) как в прошлом ролике D=30 ×2, B) D=30 ×1, C) D=42 ×1 (оригинал Race V3), D) D=60 ×1. `SPEED_2_camera_and_scale.mp4` — C, E) следящая камера с разметкой земли, F) следящая камера + крупный план ×2, A.

## 2. Длительность D без подмены текста
Race V3 теперь принимает длительность опцией: `buildDog(preset, index, {courseSeconds})`, `generateRace(seed, {courseSeconds})`, `resolveRace(seed, {courseSeconds})`; без опции всё как раньше. Правка — 5 строк в `dog4-v3-lab/model.mjs` (`speedAt` читает `dog.baseSpeed ?? BASE_SPEED`, `baseSpeed` ставится только если задана опция) и `scenario.mjs` (опция пробрасывается). Физика, события, окна, места не менялись.
* Проверка: результат с опцией **побитно равен** прежней подмене константы (оракул `tests/oracle_substitution.mjs`) для D = 20/30/42/60/120/240 × 100 сидов; без опции `resolveRace` совпадает с оригиналом на 100 сидах; повторные вызовы и перемешанные D дают тот же результат; недопустимое D (<10) — ошибка.
* Влияние на существующие тесты: `race-v3-p3-lab` T2–T4, T8–T10 PASS как раньше; **T1 теперь FAIL только по пункту `v3GitClean` (он проверяет, что файлы V3 не правились) — `signatureMismatches` по-прежнему 0 на 10 000 гонках**. Это ожидаемо и требует вашего решения: принять правку и обновить этот пункт теста, либо вернуть текстовую подмену. `dog4-v3-lab/validate|random_validate|fallback_validate` — те же результаты (в random_validate те же 10 отвергнутых сидов).
* Выбор собак, ставки, seed, спецдействия, места — прежние (влияние действий проверено тестами на D 20…240).

## 4. Переходы (реальное время, `ACCEPT_1…5`)
* Попиксельная проверка ВСЕХ путей выбора (`tools/selection_pairs_eval.py`, `selection_transitions_metrics.json`: 2 518 уникальных пар соседних кадров по всем стартовым фазам): стыки IDLE→SELECTED, SELECTED→RETURN, RETURN→IDLE — IoU силуэтов **не ниже 0,970 (Рокки) / 0,988 (Фрэнк) / 0,990 (Луна) / 0,993 (Пупс) / 0,997 (Зефир)**, сдвиг линии лап 0–1 px. «Подозрительные» пары — внутри самих SELECTED/RETURN (собственные прыжки клипов), не наши стыки. Касания верхнего края ячейки (обрезанные уши на прыжках SELECTED: Зефир 23 пары, Пупс 9, Луна 9, Рокки 4, Фрэнк 0) — это свойство утверждённых исходников.
* `ACCEPT_1` Рокки (выбор на фазах 0, 40, 77 — худший 91 кадр/3,79 с, 150) и `ACCEPT_2` Луна (фазы 4 — худший 89 кадров/3,71 с, 30, 70, 0): IDLE → ожидание ворот → SELECTED → RETURN → IDLE, 24 к/с, по тику на кадр.
* `ACCEPT_3` завершение выбора → переход к старту: переработал сцену — сначала карточки уходят на нейтральном фоне (раньше трасса просвечивала сквозь карточки), затем вуаль расходится, собаки проявляются в RACE_STAND.
* `ACCEPT_4` бабочка у всех пяти: по контактным листам кадров клипов (`BUTTERFLY_*_contact.png`) выяснено, что все собаки смотрят вверх-вправо в промежутке ≈20–80% клипа, Луна — почти вертикально вверх, Рокки пологе. Профили бабочки (`PROFILES` в `butterfly.mjs`): зависает у морды по линии взгляда, прежняя траектория была слишком высоко. Это подбор по кадрам, **синхронность с мимикой/лапой принимаете вы по ролику**.
* `ACCEPT_5` финиш → пьедестал: места, плашки, победитель реагирует; сидячих поз нет (принято вами).
* Задержка реакции на выбор — свойство правил выхода (макс. Фрэнк 4,42 с, Рокки 3,79 с, Луна 3,71 с, Пупс 3,63 с, Зефир 2,42 с).
