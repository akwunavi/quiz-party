# Фрэнк (Bulldog №1) — интеграционный пакет для Race V3

**Версия контракта:** `frenk-integration-1.0.0` (15.10.2026). Пакет собран из утверждённых анимаций, генераций не было, новой alpha не было. Production, физика V3 (`dog4-v3-lab/model.mjs`), Bulldog №4 и исходные ассеты не менялись. В игру пакет пока не подключён.

## Состав
```
integration_v1/
  contract/frenk.contract.integration.json   контракт: состояния, клипы, окна, сдвиги, тень, ассеты с SHA-256
  contract/frenk_start_shift_arrays.json     сдвиги RACE_START по категориям (режим native)
  contract/frenk_stop_v4_shift_arrays.json   сдвиги STOP V4 (stopShiftSrc / stationaryShiftSrc), = stop_v4/metadata
  atlas/frenk_{run,start,stop,sniff,bf,roll}.png + frenk_atlas.json   спрайты 207×116, 487 кадров, центр масс каждого кадра
  runtime/frenk_visual.mjs                   эталонный код: какой кадр, сдвиг и тень рисовать в момент t
  tools/check_package.mjs                    статические проверки + прогон runtime на тысячах гонок (Node)
  tools/rebuild_atlas.sh, build_atlas.py     пересборка атласа из alpha и побайтная сверка
  results/                                   результаты проверок (ниже)
```

## Как подключить
1. Физика остаётся общей: собака Фрэнка — обычная собака V3 (`buildDog` / `resolveRace`), её `dog.segments` и мировой `x` считает неизменённый `model.mjs`. Контракт на результаты гонки не влияет.
2. Загрузить пакет: `const F = await loadFrenk('<url>/bulldog1-frenk/integration_v1/')`. Он читает контракт, оба файла сдвигов и атлас.
3. На каждом кадре для дорожки Фрэнка:
   `const v = frenkVisual(F, dog, t)` вернёт `label` (кадр атласа), `shiftSrc` (сдвиг спрайта в исходных px), `window`, `category`, `diagnostic`.
   `drawFrenk(ctx, F, layout, v, x, laneY)` рисует тень и спрайт. `layout` — тот же `dog4-v3-lab/layout.json`, что у №4 (`spriteWidth`, `spriteHeight`, `spriteAnchorX`, `spriteTopOffset`).
4. Правила, которые реализует runtime (текстом — в `contract.shift.rules` и `contract.shadow`):
   * сдвиг спрайта: в STOP/FINISH по массиву STOP V4 своей категории; в стойке и действиях — `stationaryShiftSrc` последнего STOP (до первого STOP — 0); в RACE_START — массив START × (offset + 125)/125; в RUN — 0;
   * тень идёт за **видимым телом**: в RUN ровно как у №4 (якорь − 50), в стойке, SNIFF и BUTTERFLY по центру RACE_STAND, в STOP V4, RACE_START и ROLL по центру кадра со сглаживанием по 5 кадрам. На входе в STOP тень плавно сходится за 8 кадров, на краях ROLL — за 6;
   * `diagnostic` не пустой — это ошибка интеграции: подменять кадр нельзя, надо показать и разобраться.
5. Runtime — браузерный модуль. Он импортирует неизменённый `race-v3-p3-lab/src/visual.mjs` по относительному пути `../../../race-v3-p3-lab/src/visual.mjs`. При переносе в игру этот путь нужно поправить или положить `visual.mjs` рядом.

## Известные ограничения
1. IDLE и SELECTED не готовы. FRONT_STAND и FIRST_START не входят в контракт гонки: нужно решение, где экран выбора передаёт собаку в гонку.
2. Стык RUN → STOP V4: совпадение силуэта 0,73, меняется резкость; тело сдвигается до 1,8 px против шага якоря. Принято.
3. RACE_START gen3 f35 → RUN #88: до 2,8 px против шага якоря на старте гонки (свойство принятых массивов START); прищур около 0,3 с; передняя лапа скользит на толчке.
4. BUTTERFLY: двойной подъём дальней лапы, вытянутая лапа f63–70, дымка у переносицы на одном кадре, взгляд на 207 px читается слабо. Объекта бабочки в пакете нет.
5. SNIFF_PEE V3.2: лапа поднята назад, задняя лапа подёргивается и размыта при смене стойки, дальняя стопа скользит примерно на 3 px; остаток тени пола 1–2 px в двух кадрах.
6. ROLL: кадры r16 и r93 смазаны движением уже в исходнике.
7. Сдвиги STOP посчитаны для вариации скорости 1,0. При вариациях ±2 % собака доезжает на ≈ 0,4 px больше или меньше; скачков это ни в одной проверке не дало.
8. Атлас рассчитан на игровой размер 207×116. Для крупного показа его надо пересобрать с другим размером через `build_atlas.py` (не проверялось).
9. Alpha RUN берётся из git-объекта другой ветки (`8e30e51…:dog1-run-alpha.webm`). Для пересборки атласа этот объект должен быть в репозитории.
10. Подробности дефектов — `../KNOWN_ISSUES.md`, решения — `../DECISIONS.md` (п. 55–59), утверждённые версии — `../MANIFEST.json → approved_set`.
