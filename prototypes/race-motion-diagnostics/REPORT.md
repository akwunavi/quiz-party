# Bulldog RUN: диагностика движения

Изолированная лаборатория. Новые художественные концепты, Race V3, исходники собак и production не менялись. Это **тестовая траектория прежнего прототипа**, а не результат/физика Race V3. Фрэнк, Зефир и Пупс имеют независимые мировые X; у Пупса есть та же демонстрационная пауза 6,0–7,2 с, поэтому за 18 с видны смены порядка. Три дорожки используются только для читаемой диагностики.

## Установленная причина

1. В прежней камере цель — медиана X группы плюс 1, сглаживание 0,85 с и максимум 5,5 ед./с. После разгона камера движется почти так же быстро, как собаки. Мировые координаты продолжают расти, но экранная скорость `v_world − v_camera` падает почти до нуля. Например, при `t=4 с` Фрэнк движется 4,7 ед./с, Зефир 4,9 ед./с, а камера — 4,89 ед./с: относительно кадра это −0,19 и +0,01 ед./с. При `t=12 с` — 0,00 и +0,20. В начале камера ещё разгоняется, поэтому визуальное замедление кажется резким.
2. Прежняя Three.js сцена тяжела для облачного Chromium с программным SwiftShader. Повторный живой замер в 1920×1080: **37 отрисованных кадров за 6,00 с ≈6,2 FPS**, в то время как игровое время продвинулось на 5,92 с. При 24 RUN-кадрах/с такой рендер неизбежно пропускает большую часть поз. Покадровый MP4 старой сцены с 24 FPS этого не показывал.
3. Прежний `winter-arena-lab` брал произвольные 12 кадров из alpha RUN для Фрэнка и Зефира; прежний `camera-lab` использовал другие короткие диагностические атласы и 11-кадровую петлю Пупса. Эти выдержки нельзя считать подтверждением качества принятых RUN. Новая запись использует задокументированные рабочие петли и не добавляет кадры или crossfade.

## Камера и сравнение

В исправленном режиме камера проходит `X_camera = 13 + 0,70 × median(X_dogs)`. Это только правило просмотра. Мировые X, пауза Пупса, порядок участников и частота RUN остаются теми же. Собаки плавно продвигаются по экрану, а фон уходит назад; камера сохраняет участников в кадре весь 18-секундный тест. Неподвижный обзор использует более широкое поле (102 против 44 ед.), чтобы показать весь тот же пробег без панорамирования; сравнение старой и исправленной камер использует одинаковое поле 44 ед.

## Живое воспроизведение и ограничения

В новой минимальной Canvas 2D лаборатории на облачном headless Chromium: при viewport 1280×720 и 1920×1080 — около 60,0 FPS; за 6,5 с **0 пропусков 24-Гц RUN-фазы**, 0 интервалов рендера >50 мс. Дополнительный живой прогон всей 18-секундной гонки при viewport 1920×1080: 1080 отрисованных кадров, 59,95 FPS, 0 пропусков RUN-фазы, 0 интервалов >50 мс, максимальный интервал 33,3 мс. Повторы фазы на 60-Гц дисплее ожидаемы: один RUN-кадр должен показываться 2–3 экранных обновления. Данные коротких замеров: `review/BROWSER_PERFORMANCE.json`. Исходный Three.js тест и новый Canvas тест различаются количеством собак и сложностью сцены, поэтому цифры не являются чистым бенчмарком двух API.

Для обычного компьютера с проектором разумный технический путь: держать время гонки на монотонных часах, отображать утверждённый кадр по времени/состоянию, измерять RAF и пропуски в браузере на целевом 1920×1080 устройстве, ставить бюджет рендера прежде декораций. В первую очередь использовать лёгкий 2D-слой для собак и дорожек; 3D окружение возвращать только после замера аппаратного GPU и оптимизации геометрии/теней. Это предложение, не изменение production.

Визуальные ограничения: 2D alpha-собаки всё ещё плоские относительно будущего 3D окружения; эта лаборатория не решает художественную композицию. У Пупса есть тестовая остановка 6,0–7,2 с, это намеренное событие траектории. Возможное скольжение лап при разных мировых скоростях и реальная плавность на проекторном ПК требуют отдельной проверки. Игровая визуальная приёмка исправленной скорости остаётся за пользователем.

## Запуск

Из корня репозитория: `npx vite prototypes/race-motion-diagnostics --host 127.0.0.1 --port 5175`. Открыть `http://127.0.0.1:5175/`. Доступны неподвижная, прежняя и исправленная камеры; Play показывает живой RUN и текущие скорости/FPS. Источники alpha не нужны для воспроизведения, атласы включены в лабораторию. `python prototypes/race-motion-diagnostics/capture.py` только для повторной записи и измерения; для просмотра MP4 сервер не нужен.
