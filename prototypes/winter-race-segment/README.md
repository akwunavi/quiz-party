# Снежный кубок — первый участок маршрута

Изолированный браузерный фрагмент на 18 секунд. Это один вариант сцены для визуального согласования; старые отклонённые концепты не используются. Race V3, production и исходные RUN-клипы не подключены и не изменены.

## Просмотр

Из корня репозитория после `npm ci`:

```bash
npx vite prototypes/winter-race-segment --host 127.0.0.1 --port 5177
```

Открыть `http://127.0.0.1:5177/`, нажать «Старт». Для просмотра готового MP4 сервер не нужен: `review/WINTER_RACE_LIVE_18S.mp4`.

## Реализация

- Пять самостоятельных мировых X и пять полос. Фрэнк, Зефир, Пупс плюс демонстрационные дубли Фрэнка и Зефира. Пауза Пупса на 6,0–7,2 с создаёт временное отставание; другие участники обгоняют его. Траектория только диагностическая, результаты Race V3 не вычисляются.
- RUN берётся из документированных рабочих циклов: Фрэнк source #87–98, Зефир #88–99, Пупс alpha #11–22. Атласы в `assets/` экспортированы из неизменённых alpha WebM. Каждый цикл содержит все 12 последовательных кадров; позы выбираются по `floor(t × 24)`, независимо от RAF.
- Камера следует за медианой X с коэффициентом 0,70, но её скорость и ускорение ограничены. Она не догоняет группу до нулевой относительной скорости и не реагирует скачком на остановку Пупса. Координаты собак, камеры, деревьев, трибун и разметки принадлежат одной мировой системе.
- Сцена состоит из отдельно рисуемых мировых объектов: праздничная трибуна и деревянный домик, открытый лесной участок, вторая трибуна с часовой башней. Это не повтор одной фоновой картинки. Зрители ближнего ряда двигают руками и флажками; снег движется поверх сцены.
- Для этого ограниченного бокового участка выбран слоистый Canvas 2D renderer: окружение внутренне рисуется в 1280×720, alpha-собаки, локальные контактные тени, снег у лап и HUD — в 1920×1080. Это сохраняет общую камеру и чёткие персонажи при меньшей нагрузке. Прежняя перегруженная Three.js сцена в облачном SwiftShader давала около 6 FPS; выбор Canvas здесь **не определяет** архитектуру всей будущей арены. Для полноценных объёмных декораций потребуется отдельный WebGL/Three.js тест на целевом GPU либо гибридный renderer с тем же контрактом координат.

## Проверка

`capture.py` записывает **живое воспроизведение браузерного canvas** через `captureStream(30)`/MediaRecorder, затем создаёт совместимый H.264/yuv420p MP4. Он также снимает три реальные сцены 1920×1080, крупный план и собирает показатели RAF во время записи. Это отличается от покадрового вызова `renderAt` для создания видео. Скриншоты задаются точным временем через `renderAt` только для удобного сравнения участков.

Измерения, честная оценка художественных дефектов и план развития: [REPORT.md](REPORT.md). Вся лаборатория предназначена для просмотра и не связана с production RaceBoard.
