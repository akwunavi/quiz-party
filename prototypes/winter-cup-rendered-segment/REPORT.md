# Снежный кубок B × C — проверка одного рендерируемого участка

## Итог проверки

Интерактивная браузерная сцена **работает технически**, но **не достигает художественного уровня утверждённых концептов B/C**. Эту сборку нельзя считать готовым эталоном для остальных зон или утверждённой ареной. Она полезна для проверки геометрии, камеры и предела производительности текущего способа построения объектов. Продолжать остальные четыре зоны на её визуальной базе не рекомендую.

## Что реализовано

- Один зрительский участок в вечерней зимней палитре, без собак и без Race V3. Пять непрерывных ледяных дорожек, выпуклые снежные разделители и низкие борта.
- Реальные 3D-меши Three.js с мировыми координатами для поверхности, трибун, деревянных домиков, елей, фонарей, зрителей и гирлянд. При движении камеры эти объекты проходят перед ней, а не прокручиваются как единый готовый концепт-JPEG.
- Процедурные CanvasTexture для льда, деревянных досок и дальнего сумеречного неба. За основу палитры взяты сумерки C; архитектура трибун и спортивная структура дорожек следуют B. Внешние 3D-модели и текстуры не использованы; проверка сторонних лицензий не требуется.
- Камера с ортографической боковой проекцией движется по мировой X от **−4,0 до 54,14** за 18 секунд. Дальние звёзды и луна имеют меньшую скорость параллакса; трибуны, фонари и дорожки находятся в общей мировой системе. Крупных передних объектов перед дорожками нет.
- Жесты нескольких зрителей анимируются. Пять диагностических прозрачных объёмов включаются в интерфейсе; ни одна библиотека собак не подключена.

## Геометрия и читаемость

Геометрия ориентирована на шаг из `2428213`: центры пяти дорожек разделены в проекции **148,34 px** при браузерном кадре 1920×1080. Диагностический контур имеет видимую высоту **142,89 px** и ширину **188 px**; минимальный вертикальный зазор между соседями составляет **5,45 px**. Все пять помещаются в кадр. Это тестовая оболочка, а не полноценная проверка реальных alpha-масок собак. Художественные концепты показывали дорожки заметно компактнее, чем позволяет этот проверенный шаг: пять полос занимают большую часть высоты, оставляя менее трети экрана архитектуре и горам. Сохранять крупный будущий масштаб собак важнее, чем повторять пропорции иллюстраций буквально.

## Производительность и память

Замеры получены в одном облачном headless Chromium при окне **1920×1080** и внутреннем разрешении WebGL **960×540** с программным рендером. Записанный MP4 масштабирован до 1920×1080; его 30 FPS — частота контейнера, **не фактическая частота браузера**. Исходные значения находятся в `review/BROWSER_METRICS.json`.

| Непрерывный 18-секундный прогон | Без записи | С MediaRecorder |
| --- | ---: | ---: |
| Средний RAF FPS | **12,23** | **12,34** |
| Интервалы кадра >50 мс | 218 | 220 |
| Максимальный интервал | 150 мс | 100,1 мс |
| Измеренная длительность мирового времени | 18,0 с | 18,0 с |
| JS heap на момент завершения | 42,8 MB | 20,0 MB |

Меши статичных объектов объединены по материалам и пространственным блокам, динамические зрители отделены: **3382 исходных меша → 227 статичных блоков**, на контрольной позиции **77 draw calls, 103 434 треугольника**. В памяти WebGL — **185 геометрий и 4 текстуры**. `renderer.info.memory` даёт количество ресурсов, но не размер видеопамяти в байтах; WebGL не раскрывает надёжный GPU heap. Показатель JS heap также не равен полной памяти процесса Chromium. Значения 12,23 и 12,34 FPS практически одинаково низкие; небольшая разница между ними не доказывает ускорение от записи.

Для сравнения облегчённый Canvas-участок из `2428213` достигал **42,57 RAF FPS без записи** при полноразмерном слое 1920×1080. Текущая сцена остаётся существенно медленнее даже при внутреннем 960×540. Запись MP4 не является доказательством плавности; на целевом компьютере с GPU требуется отдельный тест.

## Отличия от выбранных B/C и причина

| Намерение | Фактический результат | Причина |
| --- | --- | --- |
| Архитектура спортивного кубка B | Трибуны и домики имеют пространственную форму, но выглядят упрощёнными | Модели собраны из примитивов и процедурной текстуры, без подготовленных художественных GLB, нормалей, фасадных атласов и lightmap |
| Живые выразительные зрители B/C | Толпа видна, часть людей двигает руками, но формы и ряды повторяются | Повтор одного упрощённого меша с вариациями цвета; нет библиотеки индивидуальных персонажей и жестов |
| Сумеречный свет C | Цвет неба, луна и гирлянды присутствуют | Отсутствуют запечённое освещение, мягкие тени и согласованная световая модель объектов; их добавление в текущем WebGL ещё снизит FPS |
| Объёмный снег и выразительный лёд | Рельеф разделителей и текстура льда есть, но покрытие выглядит полосатым и плоским | Не хватает подготовленного материала, карт нормалей и ручной композиции бликов/следов; большая экранная площадь поверхности усиливает повторяемость |
| Плавное сопровождение | Мировое время и X камеры стабильны | Частота браузерного рендера слишком низка для убедительного движения в облачном программном WebGL |

## Техническое решение перед следующим художественным проходом

1. Подготовить **небольшой модульный набор авторских или проверенных по лицензии ассетов**: 1–2 типа трибун, chalet-фасады, несколько качественных елей, три группы зрителей с жестами, фонари/гирлянды. Не собирать их во время кадра из сотен отдельных цилиндров и коробок. Использовать запечённые текстуры/свет и общий атлас.
2. Сохранить реальные мировые X/Z и пятидорожечный контракт. Для дальнего плана допустимы 2.5D импосторы **отдельных объектов** с собственными координатами и параллаксом; целиком прокручиваемый концепт-арт не подходит.
3. Проверить модуль в изоляции на целевом проекторном GPU. Цель — минимум 30 стабильных FPS при игровом 1920×1080 и без пропусков визуальных фаз. Если целевой GPU слабый, использовать гибрид: заранее рендерить отдельные статичные декорации в атлас и компоновать их Canvas 2D по мировой координате, как в `2428213`.
4. После этого заново оценить композицию B/C с одной настоящей alpha-собакой **только для масштаба**, не подключая Race V3, и лишь затем решать вопрос о полном маршруте.

Race V3, animation assets, production и другие работы в репозитории не изменены. Merge, deploy, Kling и иные платные генерации не выполнялись.
