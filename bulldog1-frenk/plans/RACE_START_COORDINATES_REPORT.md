# RACE_START: проверка системы координат V3 и непрерывности (до Kling)

Дата 13.10.2026, HEAD ветки `f58414a0`. **V3, Bulldog №3/№4, production, STOP, RUN, RACE_STAND не менялись. Kling не запускался.** Исследовалась только изолированная лаборатория `dog4-v3-lab/` (`model.mjs`, `app.mjs`, `layout.json`, `manifest.json`) и спрайт-листы Dog4 из git.

## 1. Как устроено позиционирование в V3
- **Физическая координата** собаки — это только `progress ∈ [0,1]` (`stateAt`, `model.mjs`). Она растёт от скорости `BASE_SPEED·base·variation` и **не зависит ни от какого PNG/WebM**.
- **Экранная точка:** `x = startX + progress·(finishX − startX + finishControlOffset)` = `406 + 1170·progress` (на холсте 1920×1080).
- **Отрисовка клипа** (`app.mjs: sprite(clip, frame, x−spriteAnchorX, lane−spriteTopOffset)`): кадр любого клипа (BASE, START, RUN, STOP, события) рисуется **одним и тем же якорем**: `spriteAnchorX = 148`, `spriteTopOffset = 110`, размер спрайта 207×116. Спрайт-лист: ячейка 178×100 = исходный кадр 1276×720, уменьшенный; на экране 207/1276 = **0,1622**.
- **Какая точка якорь:** комментарий в коде: при progress = 1 «задний контур BASE уходит за линию финиша». Проверено на спрайтах: якорная колонка в ячейке = 127,3 px, задний контур стойки Dog4 = 50 px, то есть якорь привязан к заднему контуру стойки (≈ +554 px исходного кадра правее него).
- **Offset на клип:** **отсутствует.** Нет ни постоянного смещения на клип, ни рампы, ни масштаба на собаку. Непрерывность Dog4 обеспечена тем, что в его клипах корпус остаётся в одной колонке кадра (границы клипов расходятся на ≤ 3 px ячейки ≈ ±22 px исходного кадра ≈ ±3,5 px на экране).
- Видео в V3 считается «на месте»: сдвиг по трассе делает `progress`. Любое перемещение внутри видео **прибавляется** к нему.

**Вывод по задаче 1:** центр экранного PNG не является физической координатой; но так как якорь один на всё, на границе клипов корпус обязан стоять в одной и той же колонке кадра. Постоянный offset на клип V3 сейчас применять не умеет.

|---|---|---|

Контроль замыкания цикла: RUN #97 (628,6) → STOP (+111) → стойка (736,6) → RACE_START (−143 по центру масс или −125 по головам и габариту) → RUN #90 (593,5) → … #97: сходится (≤ 3 px). Расхождение между оценками −125 и −143 из-за разной массы ног (в стойке ноги вертикальны); по ориентирам «голова, зад, габарит, наложение» совпадение −125 ± 5, поэтому для offset берётся **125** (остаток ± 3 экранных px).
Предыдущие переходы из утверждённого: RUN #96 → STOP f1 (≈ #97): центр 639,6 → 625,1 (обычный шаг); первый START #63 → #87: 619,2 → 612,3. Оба в норме.

## 5. Вывод по непрерывности
**При существующей архитектуре V3 RACE_START со сдвигом −125 даёт скачок; без сдвига клип не получается «на месте».** Варианты (минимально):
- **R1 (рекомендую): минимальный интерфейс в данных клипа**, V3 логика гонки не меняется: в манифест добавить на клип `shiftFrom` и `shiftTo` (в px исходного кадра), в `sprite()` рисовать с `x − spriteAnchorX + lerp(shiftFrom, shiftTo, smoothstep(u))·spriteWidth/1276`. Для RACE_START: `shiftFrom=+125`, `shiftTo=0`; все остальные клипы Френка `0/0`. Kling при этом генерирует собаку **на месте** (без искусственного перемещения), а непрерывность даёт движок.
- **R2 (без правок V3):** START-кадр без сдвига (центр масс 736,6), а в видео «запечь» −125 px по кадру (как в STOP запечено +98). Тогда Kling должен сместить собаку на 125 px влево относительно камеры при разгоне, что нефизично. Не рекомендую.
Прочие замечания к интеграции (не блокируют генерацию): якорь и масштаб в V3 глобальные для Dog4. Для Френка нужен свой якорь: задний контур стойки 403 + 554 ≈ 957 px кадра = **≈ 155 px холста** (у Dog4 148); длительности START/STOP в `model.mjs` константы (1 с / 37 кадров), у Френка 3 с / 73 кадра; фаза входа в RUN (#91) и выхода (#96→STOP) отличаются от Dog4 (прелюдия 11 кадров + цикл 12), нужны метаданные клипа `runEntryIndex`, `stopEntryIndex`.

## 6. Подтверждение кадров
- **START-кадр** = RACE_STAND, сдвиг −125 (`DOG1_RACE_START_START.png`): задний/передний контуры совпадают с END (RUN #90) на 1 px (278/894 против 279/893). Остаётся: центр масс 611,6 против 591,5 (из-за позы), это нормальное изменение при разгоне.
- **END-кадр** = RUN #90 (`DOG1_RACE_START_END_run90.png`), затем реальный #91. Подтверждено: следующий шаг цикла — бросок вперёд.
- Критерий приёмки результата Kling добавлен: последний кадр совпадает с #90 по контурам не хуже ± 5 px и по земле ± 5 px.

## 7. Блокирующие дефекты
1. **V3 не поддерживает смещение на клип** → без R1 (или R2) переход события → RACE_START даёт скачок 20 px холста. *Блокирует интеграцию, но не блокирует генерацию в Kling.*
Не блокирующие: STOP несёт +18 экранных px собственного перемещения (V3 считает, что в клипе собака на месте; визуально собака на время события стоит на 18 px впереди физической точки, затем возвращается рампой RACE_START); глобальные якорь/длительности/фазы RUN в `model.mjs`; остаточная тень в #36 первого START (принято).
