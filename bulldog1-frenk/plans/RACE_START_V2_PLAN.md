## 6. Принцип компенсации координат (не реализуется в V3)
Спрайт RUN сидит на 142 px (23 px игрового масштаба) позади спрайта стойки (центры 736 → 594). Эту разницу должен «съесть» START за счёт движения движка.
1. Отрезок f1…f16: движок стоит (E=0), лапы стоят → **C = 125 константа** (спрайт едет с корпусом).
2. С первого отрыва лапы в V2: движок стартует (профиль скорости, ограниченный константой V0 = 171,7 px/с), C убывает 125 → 0, **скорость убывания не больше скорости движка плюс собственное движение корпуса в кадре**, чтобы экранная скорость не была отрицательной. Профиль C строится **по кадрам принятого клипа** (нижняя монотонная огибающая сглаженного положения, как в salvage-отчёте), а не формулой.
3. Условие выполнимости: ΔE + (594 − 574) ≥ 125 + 36(осадка) − …; по расчёту **длительность тела V2 ≥ ≈1,35 с** (при 1,0 с чистое продвижение отрицательное — вариант V4 из salvage). В контракте V3 это значит: у клипа своя длительность и массив C по кадрам (`shiftFrom=+125, shiftTo=0` + профиль), а константа START 1 с неприменима. Ничего не менялось.
