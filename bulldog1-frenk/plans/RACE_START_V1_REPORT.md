**Дефекты:**
1. **Последний кадр ≠ RUN #90**: IoU 0,564, разница цвета 30,7 (норма обычного шага: IoU ≈ 0,68, цвет ≤ 26). Требование «последний кадр совпадает с #90» не выполнено.

5. Прямого стыка с циклом RUN в пределах обычного шага нет: лучший `f49 → #90` — IoU 0,573 / цвет 30,1 (хуже нормы). Рябь центра ±30 px за шаг.

## Компенсация координат
- Профиль зависит от самого клипа: клип сам уезжает назад на ≈59 px при подкрадывании и затем рывками ±30 px за шаг, поэтому никакая гладкая кривая не убирает обратное скольжение целиком.
- Пропорциональный профиль выше: минимальная сглаженная скорость −78 px/с (27 кадров отрицательных); простая smoothstep за 1 с: −235 px/с; профиль, гасящий дрейф клипа (`125 → ~164 пик → 0`): −52 px/с.
- Вывод: профиль надо выводить из принятого клипа и движения игры. `shiftFrom/shiftTo` на клип (+125 → 0) остаётся основой контракта; автоматический smoothstep 1 с не утверждён. В V3 ничего не реализовано.

## Итог и решение
V1 как есть я бы не принимал: нарушены последний кадр и ритм, в начале долгое подкрадывание. Варианты для решения пользователя: (а) принять запасной гибрид (f1–51 + реальные #58–63) с оговорками; (б) перегенерировать (≈18 кредитов) с правкой промпта/кадров; (в) оставить реальный первый START для всех собак и RACE_START не делать. Без решения ничего не запускаю.
