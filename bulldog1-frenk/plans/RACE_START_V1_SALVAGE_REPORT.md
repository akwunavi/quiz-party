## Метод и оговорка по цифрам
Стыки считались заново на кадрах с alpha (RGBA на плите фона, половинное разрешение): IoU масок и средняя разница цвета по объединению масок. Эта методика даёт другие числа, чем в V1-отчёте (там f51→#58: 0,727/25,5, здесь 0,839/32,6), поэтому нормой взят обычный шаг самого RUN по тому же методу: **IoU 0,757–0,84, цвет до 39,6**. Числа сравнивать только внутри этой таблицы. Каждый стык смотрел глазами (`hy_seams_sheet.png`), одних метрик недостаточно: напр. стойка → #90 проходит по числам (0,756/36,9), но визуально это скачок из вертикальной стойки в присед галопа.

## Что внутри клипа V1 (кадры, `hy_clip_early.png`)
- f1–6 статичная стойка (нужна лишь как удержание).
- f7–10 лицо жмурится (глаза закрыты в f8–10), корпус оседает.
- f12–27 «присед»: корпус почти неподвижен (IoU соседних кадров 0,97–0,99), центр уезжает назад с x≈609 до 545 (−64 px). Это и есть затянутый разгон (~0,7 с).
- f28–36 толчок: тёмное прищуренное лицо, размытие. f37+ галоп, ритм 8–9 кадров.
Из приседа в кадры настоящего RUN входа нет: f12–f28 → любой реальный кадр не проходит (лучший из приседа f26→f28 клипа). Из стойки в реальный кадр единственное «проходящее по числам» f1→#90 — визуальный скачок (отвергнут). Из приседа в f40 (минуя толчок f29–36) тоже не проходит (f26→f40 ниже нормы). Значит **прищуренный рывок f28–36 из клипа вырезать нельзя**.
Рабочий вырез приседа: f12→f22 (0,883/31,5, глазами почти идентичны), f1→f7 (удержание стойки).

## Дрейф и компенсация (диагностика, V3 не менял)
Скрипт `analysis/hy_comp.py`. Движок: V0 = 171,7 px/с исходного кадра, профиль START `(V0·T/2)(2u³−u⁴)`, T = длительность ускоряющей части. Компенсация вывожу из самого клипа: экранное положение сглаживается окном 9 кадров (один шаг), строится нижняя монотонная огибающая (не ниже стартовой точки), разница к простому профилю `125·(1−(2u³−u⁴))` и есть доп. сдвиг. Это не авто-smoothstep, а профиль под конкретный клип.
| | простой профиль: мин. скорость / откат | выведенный профиль: доп. сдвиг макс / пик «проскальзывания ног» | чистое продвижение за START | вывод |
|---|---|---|---|---|
| V1 | −87 px/с, откат 46 px (7,5 лаб. px) | 7,4 лаб. px / 22 лаб. px/с | +83 px | жизнеспособен с профилем под клип |
| V2 | −91 px/с, 56 px | 9,1 / 20 | +126 px | жизнеспособен, дрейф заметнее |
| V3 | −85 px/с, 40 px | 6,4 / 21 | +35 px | жизнеспособен; собака почти стоит на экране 2 с (движок уходит вперёд, спрайт держится рядом) |
| V4 | −111 px/с, 47 px | 7,6 / 20 | **−15 px** (за 1,46 с движок уходит на 125, спрайт должен отъехать на ~140 — итог назад) | **непригоден** при нынешнем движке |
| V5 | −154 px/с, 93 px | 14,7 / **210** | +43 px | **непригоден** (скачок профиля на стыке) |
«Проскальзывание ног» — сдвиг спрайта при стоящих лапах (foot-skate), цена гашения обратного дрейфа; 6–9 лаб. px на пике 20 лаб. px/с видно, но это не телепорт. Полностью без обратного скольжения и без проскальзывания ни один вариант не обходится: сам клип уезжает назад на 64 px в присед.
Базовая причина смещения: в RUN спрайт сидит на ≈142 px (23 лаб. px) позади точки стойки (центр 736 → 594); эту разницу должен «съесть» START.

### Что изменить в новой генерации
1. **START-кадр = готовый присед, а не стойка**: взять настоящий кадр V1 f12 (поза и лицо чистые, глаза открыты; он уже в системе координат RUN) и подать его первым кадром. Вход в присед даёт готовый кусок V1 f1–f12 (f1→f7→f12: плавные шаги; прищур f8–10 остаётся, можно резать f7→f11 только после визуальной проверки).
2. **END-кадр = RUN #90 в той же системе координат** (как сейчас), клип без сдвига на 125 px: расхождение стойка ↔ RUN уже закрыто f1–f12.
3. **Хореография: без паузы и подкрадывания**: «толчок в первую долю секунды», глаза открыты и смотрят вперёд на всём протяжении, рот приоткрыт в улыбке, никакого прищура/склонения головы; ритм «два шага в секунду, каждый шаг ровно полсекунды»; последний кадр — фаза толчка #90. Запретить «ступор», раскачку назад, смену выражения.
4. Длительность оставить 3 с (минимум модели), в монтаже обрезать по лучшему стыку с #90 (в V1 f49 дал 0,925).
5. Дрейф в кадре: просить «собака остаётся на месте кадра» уже просили — Kling всё равно уехал на −64 px; решается профилем сдвига под принятый клип, не промптом.
Ориентиры приёмки новой генерации: стык последнего кадра с #90 ≥ IoU 0,85 / цвет ≤ 30 по той же методике; нет статичных кадров (IoU соседей ≥ 0,97) дольше 0,3 с; нет кадров с закрытыми глазами.
