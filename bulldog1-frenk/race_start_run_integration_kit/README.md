## Что исправлено по двум замечаниям
1. **Контракт.** В `CONTRACTS.md` разделены: действующий физический контракт V3 (константы START=1 с, STOP=37/24 с, RUN_JOIN=23/24 с), предлагаемый контракт Френка (31 кадр, не принят) и требования синхронизации. Совместимый режим «native»: физика START=1 с остаётся, визуальный START играет 1:1 с выездом на 0,71 с, откат ≤ 0,60 px.
2. **Компенсация.** Откат сглаженной позиции доведён с 1,15 до **0,80 px (NORMAL)** одним минимальным изменением: производная коррекция N2 применяется **два прохода вместо одного** (та же формула, окно 9 кадров, сглаживание 5 кадров). По остальным показателям: шаг стыка −1,33 px (было −1,46, у исходного A −2,66), шаг после конца затухания 1,71 px (без нового скачка), вторая разность в конце разгона 2,14 против 4,37 у A, пик скорости смещения 192 исх. px/с (как у A), дополнительный сдвиг до 17,9 исх. px (2,9 px холста), фазы лап и кадры не менялись, задержек нет. Для остальных категорий скорости откат 0,57–0,88 px; массив NORMAL нельзя применять к другим категориям (SLOW 2,3 px, VERY_SLOW 4,0 px), поэтому в комплекте пять массивов. Попытка сильнее (окно 7 + 2 прохода) дала 0,58 px ценой сдвига 21,7 px и пика 212 px/с и отвергнута как компромисс; вариант smoothstep (0,99 px) даёт сдвиг до 43 px и отвергнут.

## Условия совместимости с текущей физикой V3
- У1. Таблица кадров и сдвиг не участвуют в расчёте прогресса и `crossing`; прогресс движка идентичен исходной сборке (разница 0, `race_start_run_join_v1/integration_check/check_results.json`).
- У2. Режим A «native» не требует изменений V3, но каждая собака, отличная от Bulldog №4, сегодня всё равно получает константы №4 для STOP и RUN_JOIN: пока они общие, STOP Френка вне комплекта и не решён.
- У3. Режим B требует принятия per-character метаданных (`velocityRamp`, `runJoin`) и перепроверки баланса, поскольку START Френка 1,29 с против 1 с у №4 (+0,146 с потери времени за каждый START относительно START=1 с при равной скорости).
- У4. Для каждого события требуется собственный массив сдвига под категорию скорости после события.

## Необходимые регрессионные проверки (перед включением)
1. Прогресс/`crossing`/места/`effectiveSeed` на наборе seed (≥10 000, как `fallback_results.json`) совпадают бит-в-бит при исходном и итоговом стыках.
2. `node validate.mjs`, `random_validate.mjs`, `fallback_validate.mjs`, `balance_audit.mjs 20261013 10000`: выходы Dog4 неизменны.
3. Проверка метаданных: `frame(velocityRamp.end) = RUN #90`; кадры 0–40 идентичны исходной сборке; 41–42 = #88, #89; цикл #98→#87.
4. Спрайт: откат ≤ 1 px, шаг стыка ≤ 2,7 px, отсутствие нового скачка после затухания, для всех пяти категорий.
5. Крупный план и масштаб спрайта, 6 повторов стыка, без двойных контуров.
6. Решение по сетке STOP (У2) подтверждено отдельным расчётом.
