# Контракты длительности: что действует, что предлагается, что требуется (14.10.2026)
Три уровня разделены намеренно. **31 кадр (1,2917 с) НЕ является действующим физическим стандартом V3.** Это параметр предлагаемого контракта персонажа.

## A. Действующий физический контракт V3 (изолированная лаборатория, не production)
Источник: `dog4-v3-lab/model.mjs`, `scenario.mjs`, `docs/bulldog-race/APPROVED_RULES.md`. Ничего из этого не менялось.
- **Константы на всех собак** (`model.mjs` строки 4–7): `STOP = 37/24` с, `START = 1` с, `RUN_JOIN = 23/24` с, `LOOP = 12/24` с; в `buildDog` стартовое `BASE = 0,5` с (строка 76). Констант на одну собаку нет: сейчас «пять визуальных копий Bulldog №4» (`APPROVED_RULES.md`).
- **START** (строки 77, 102, 168): сегмент длительностью ровно `START` = 1 с, прогресс `p0 + v·START/2·2·(u³ − u⁴/2)`, скорость `v·smooth(u)`. Он начинается сразу после BASE или действия.
- **Кадры** выбираются чистой функцией времени `frameFor` (строки 145–158). Для №4 START: 40 кадров на 1 с (24 кадра по 72 fps + 16 по 24 fps), RUN: пролог 0–10 и цикл 11–22 при 24 fps.
- **Выравнивание STOP по циклу RUN** (строки 64–71): `первый STOP = runStart + RUN_JOIN + k·0,5 с`.
- **Выполнимость раннего события** (строка 85) использует `START/2 + RUN_JOIN + STOP/2`.
- **Результат гонки** определяется аналитическим `crossing`, не зависит от FPS и содержимого кадров (`APPROVED_RULES.md`).
- `ANIMATION_CONTRACT.md` (таблица) формулирует для START «фактическое время клипа, в V3 №4 1 с», то есть принцип «длительность из клипа» заявлен в документах, но реализован в коде только как константы №4.

- `runJoin` (первое допустимое начало STOP после начала RUN): 7/24 с (после #96, период 12 кадров). Значение предлагается, не принято.

## C. Требования к синхронизации визуальных кадров и физического времени
1. Физика (прогресс движка, `crossing`, места) считается только из физических параметров (A или B). Таблица кадров не участвует.
2. Таблица кадров — чистая функция индекса окна START и не должна менять индекс RUN #90 относительно конца физического разгона (в варианте B: `frame(43) = RUN #90`).
3. Сдвиг спрайта (`shift`) только визуальный: массив на категорию скорости, не меняет физику; критерии: откат сглаженной позиции ≤ 1 px холста, шаг на стыке ≤ 2,7 px, отсутствие нового скачка после конца затухания.
4. Начало STOP определяется сеткой `runStart + runJoin + k·0,5 с`; на входе в STOP кадр RUN должен быть #96.
5. Ни один визуальный кадр не добавляется ожиданием и не дублируется для подгонки времени.

## D. Совместимый способ показать START Френка без изменения физики V3 (режим A «native»)
Физика остаётся действующей: START = 1,0 с с индекса 0 (24 кадра), затем RUN на крейсерской скорости. Визуальный START идёт 1:1 в естественном темпе до `visualJoin` (41 кадр, 1,71 с), то есть **«визуальный выезд» на 0,71 с за пределы физического START**, в течение которого движок уже на крейсерской скорости, а спрайт ещё в галопе gen3 (клип бежит «на месте», сдвиги `shift` убирают скольжение).
Расчёт (`shift_arrays.json`, `modes.native`):
| категория | откат, px | шаг стыка, px | сдвиг якоря за 0,5 с приседа, px | макс. дополнительный сдвиг, исх. px |
|---|---|---|---|---|
| VERY_SLOW 0,75× | 0,60 | −1,54 | 1,96 | 27,4 |
| SLOW 0,88× | 0,53 | −1,51 | 2,30 | 18,8 |
| NORMAL 1× | 0,54 | −1,48 | 2,61 | 16,1 |
| FAST 1,12× | 0,19 | −1,40 | 2,93 | 18,0 |
| VERY_FAST 1,25× | 0,00 | −1,25 | 3,26 | 20,1 |
Движок сдвигает якорь на 2–3,3 px холста, пока Френк ещё приседает (скорость START растёт с u=0); в режиме `hold_static` спрайт стоит на месте (сдвиг компенсирует дрейф), поэтому до толчка собака не скользит, а якорь опережает спрайт максимум на 3,3 px и к `visualJoin` затухает. Альтернатива, растянуть клип 41→24 кадра, отвергнута: темп галопа ×1,7 (период 13 → 7,6 кадра) выглядит неестественно, и после стыка темп замедлился бы.
Оговорка: режим A не решает сетку STOP. По текущим константам V3 первый STOP стоит на `runStart + 23/24`, в нашем окне это `idx 47` с предыдущим кадром RUN #93, а STOP Френка ждёт #96: сдвиг фазы 3 кадра. Для режима A нужен либо per-character `runJoin` (как в B), либо другой стык (из проверенных близкий по качеству f31 → #88, фаза расходится на 1 кадр; визуально не оценивался). Это нужно решить до любых событий с остановкой.
