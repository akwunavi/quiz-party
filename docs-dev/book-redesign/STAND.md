# Стенд «Книги» (`ny_book`) — этап 2, первая половина: стенд + базовые снимки

Дата: 12.11.2026, код 10.64 (`src/` не менялся). Снимки — **текущая** тема `ny_book` до редизайна.
Браузер был: headless Chromium из Playwright 1.56 (`/opt/pw-browsers`), `deviceScaleFactor: 1`.

## 1. Что это и как запустить

Настоящий проектор (`HostScreen` и все его экраны) из настоящей сборки, на локальном сервере бара
(`local-server/server.mjs` → `createServer`), без облака и без живой базы. Состояние игры пишется
сценариями через тот же API, которым пользуются пульт и телефоны.

```bash
# всё сразу: медиа → vite build → сервер на 7399 → 38 сценариев × 3 вьюпорта + прогон reduced-motion
QP_BOOK_SCRATCH=/путь/к/scratch node e2e/book/shoot.cjs --set baseline
# повторно без пересборки, только часть сцен/вьюпортов (замеры дописываются в measure.json, не стираются)
QP_BOOK_SCRATCH=… node e2e/book/shoot.cjs --set baseline --no-build --only 08c,15-finale --vp 1899x905
# только прогон с prefers-reduced-motion (замеры анимаций, без снимков)
QP_BOOK_SCRATCH=… node e2e/book/shoot.cjs --set baseline --no-build --only-reduced
# стенд «руками»: поднять сервер и открыть в браузере http://127.0.0.1:7399/quiz-party/#/?room=stand
QP_BOOK_SCRATCH=… node e2e/book/stand.mjs --no-build
```

Полный прогон — около 15 минут (≈5–6 с на снимок). Что куда пишется:

| что | где | в git |
|---|---|---|
| сборка приложения | `<scratch>/book-app` (не `dist/`, не `docs/`) | нет |
| данные сервера, медиа | `<scratch>/book-data` (пересоздаются на каждом запуске) | нет |
| полные PNG | `<scratch>/shots-png-<набор>/` | нет |
| WebP ≤ 300 КБ (на деле 30–220 КБ) | `docs-dev/book-redesign/shots/<набор>/<NN-сцена>-<w>x<h>.webp` | да |
| замеры | `docs-dev/book-redesign/shots/<набор>/measure.json` | да |

Файлы стенда (`e2e/book/`, линтером не проверяются — Node/Playwright/Python, как `scripts/`):

- `stand.mjs` — медиа (`media/gen.py`), сборка, сервер, `POST /api/arm`, заливка двух пакетов `POST /api/pack/<id>`.
- `make-pack.mjs` — демо-пакет `ny_book` по типам `src/types/quiz.ts`, 8 раундов (ниже).
- `media/gen.py` — Pillow: картинки 3:4, 16:9, 1:1, 4:3, 9:16, 21:9 с подписью пропорции, два PNG с альфой
  (звезда + полупрозрачный ореол), 4 картинки-варианта, картинка ответа; 24 тона по 14 с (mp3 системным
  `ffmpeg`, без него — WAV).
- `scenes.mjs` — 38 сценариев (ниже). Каждый: `/stand/reset` → `POST /api/teams` → `POST /api/answers` →
  `PATCH /api/session`, всё с `X-QP-PIN: 000000`.
- `shoot.cjs` — Playwright: новая вкладка на каждый снимок, `page.clock.install()`, ждёт селектор готовности,
  `img.complete`, `document.fonts.ready`, даёт сцене `settle` мс, `clock.pauseAt` (+ `clock.runFor` для
  JS-каскадов: строки финала, `StagedChoices`, `checked` разбора), доигрывает конечные CSS-анимации
  (`getAnimations().finish()`, бесконечные не трогает) → снимок → замеры.
- `measure.cjs` — rect ключевых узлов (список из PLAN §6.1 + `.rules-frame`, `.ri-main`, `.p-teams`,
  `.mel-theme` и др.), попарные пересечения блоков, выход за viewport и за видимые поля страниц,
  `scrollHeight > clientHeight`, computed шрифты `.q-text`/`.q-recall`/`.answer-main`/`.fin-table td`
  (+ `document.fonts.check`), геометрия обложки/страниц сцены против viewport, `--u`, `animationName`
  с длительностью (для прогона с reduced-motion), факт `playing` у `<audio>`.

## 3. Обходы и известные ограничения стенда

1. **Сборка НЕ «без VITE_*»** (PLAN §6.1 ошибается): `src/lib/supabase.ts` вызывает `createClient` при
   импорте, supabase-js на `undefined` бросает «supabaseUrl is required» — белый экран и в локальном режиме.
   Стенд собирает с `VITE_SUPABASE_URL=http://127.0.0.1:7399/sb` (адрес самого стенда) и ключом-заглушкой.
2. **Пакет через PostgREST-эмулятор.** В локальном режиме проектор всё равно читает пакет через
   `loadPack` → `supabase.from('packs'|'pack_rounds'|'pack_questions')`, а `GET /api/pack` не использует
   вовсе. Стенд отвечает на `/sb/rest/v1/*` (только чтение) снимками, залитыми `POST /api/pack/<id>`;
   плюс `/sb/rest/v1/teams` (его читает `ShowAnswers`). Прочее под `/sb/` — 401, как недоступное облако.
3. **`/stand/reset`** — служебный путь стенда (не `local-server`): чистит команды/ответы/сессию между
   сценариями. У API сервера нет «удалить все ответы», а ответы удалённых команд всплывали бы на разборе.
4. **Проектор без PIN — только чтение.** Его авто-переходы (раскрытие через 3 с, сторож мелодии,
   автопроверка `is_correct`, статус `melody.audio`, шаги финала) получают 403 и тихо не применяются —
   снимок показывает ровно записанное состояние. Следствие: в консоли мелодии три ошибки 403 —
   ожидаемо. Пульт/телефоны стенд не открывает (только проектор).
5. **Часы.** `page.clock` останавливает JS-таймеры; CSS-анимации идут по реальному времени — поэтому
   конечные (не бесконечные) анимации доигрываются принудительно. Снег/мерцание/canvas `Atmosphere` на
   снимках — случайный кадр: попиксельное сравнение «до/после» должно маскировать сцену или сравнивать
   замеры, а не пиксели фона.
6. Живой пакет (PLAN §6.3) не снимался: к базе не подключались по заданию.
7. Не снимались (не входили в первую половину): 3840×2160 и 1280×1024, регресс других тем
   (classic/potter/new_year/ny_home), интро/кино, табло между раундами, блиц/скрэмбл/3 попытки/своя игра/
   спринт, пульт и телефон, этапы мелодии кроме idle/spinning/snippet.

## 4. Проблемы на базовых снимках (текущая `ny_book`)

Числа — из `shots/baseline/measure.json`; «на глаз» — по PNG.

**Геометрия книги и масштаб**
- **1899×905:** сцена `cover` масштаб 0.989, сдвиг −81.6 px; обложка срезана сверху на 48 px и снизу на
  62 px, страницы — на 32/42 px. Верх книги и гирлянда флажков уходят за край экрана (видно на всех
  `*-1899x905`). Контент при этом идёт в `--u` = min(0.989, 0.838) = **0.838**: книга и вёрстка живут в
  разных масштабах (F11 подтверждён замером). На 1366×768 (≈16:9) обрезки нет: масштаб 0.711, поля 0.
- `LinkBadge` («ОБЛАКО») на 1899×905 стоит левее видимых страниц на 61 px (на столе).

**Лобби**
- Вымпелы команд не помещаются: `.p-teams` высотой 790 px при 16 командах выходит за низ экрана на
  60 px (1920×1080), 141 px (1899×905), 43 px (1366×768); при 24 командах — на 428 / 505 / 305 px (два
  последних ряда вымпелов за экраном). Плюс `.p-teams` шире контейнера: scrollWidth 1125 при 1082.
- С 9+ команд вымпелы налезают на домик и ели (в 3 ряда), читаемость имён падает.
- Окно составов перекрывает вымпелы и QR (QR поднят над затемнением намеренно — это контракт).

**Заставка раунда**
- `02-rules`: длинное название раунда («Разминка у новогоднего камина») рубится на «РАЗМИНКА / У /
  НОВОГОДНИ… / КАМИНА» и **срезается рамкой правил** (`.ri-main` scrollWidth 713 при 516 на 1920;
  507/310 на 1366). Надпись «РАУНД» у бейджа слева сверху закрыта флажком гирлянды.

**Вопрос**
- Подложки картинок: `.q-img` — белая карточка во всю ячейку, а картинка по `object-fit: contain`
  меньше неё → **большие белые поля** вокруг 3:4, 9:16, 21:9 и прозрачного PNG (06, 07, 08, 08b, 10-recall).
  Прозрачный PNG лежит на белом прямоугольнике. Наклон ±1.2° у карточек есть, у картинок внутри — тоже.
- Шапка (`.host-topbar`, высота 124 px на 1920 из-за розетки) пересекается с рамкой текста/рядом
  картинок на 24–36 px на всех вопросах с картинками (05–08, 08g); визуально текст не упирается в розетку
  только потому, что строки короткие и по центру.
- `.q-text` везде переполнен на 2–5 px по высоте (свисание букв) — шум, не баг.
- `08c` (4 картинки-варианта): плашки разной высоты, бейджи букв на разной высоте (у «Б» сразу под
  картинкой, у остальных внизу ячейки); подписи вариантов под карточками разной высоты.
- **Буквы вариантов (А/Б/В/Г) в бейджах набраны декоративным шрифтом** — читаются как «Λ», «Ь», «К»
  (08c, 11b). Так же номер вопроса «7» в `.qnum` выглядит как «Т» на 1899×905.

**Повтор вопросов (recap)**
- `10b-recap` с длинным вопросом: текст **не вписан** — `.recap-body` scrollHeight 653 при 410 (1920),
  519/344 (1899), 464/292 (1366); верх текста залезает под шапку и гирлянду (пересечение с
  `.host-topbar` 1240×58 на 1920). Кегль 48–58 px — подгон не сработал.

**Разбор**
- Шрифт повтора ≠ шрифт вопроса (F4 подтверждён): `.q-text` PT Serif **700 normal**, `.q-recall` PT Serif
  **400 italic** 24 px.
- `11-revealed-plain`: колонка ответов команд не вмещает 8 команд — `.team-answers` 784 при 656
  (1920), 779/549 (1899), 719/466 (1366), `overflow:auto` без видимой прокрутки: последняя команда
  (иногда две) просто не видна. Имена команд в карточках — декоративным шрифтом и обрезаны многоточием
  («мандар… и шампа…», «северн… олени»).
- `12-revealed-answer-media`: блок ответа переполнен — `.answer-block` 658 при 503 (1920), 485/401
  (1899), 485/314 (1366), `overflow:hidden` → **пояснение 400 знаков обрезано посередине фразы**, а
  `.answer-media` (758 px) выше самого блока и пересекается с `.q-recall` (512×91 на 1920, 331×121 на 1366);
  белая подложка картинки ответа обрезана краем блока.
- `10-recall-A`: «Ответили 5 из 8» — тёмная неоновая капсула внизу слева, поверх края книги (вне темы).

**Мелодия**
- Доска 4×6: длинная тема «Песни из кинофильмов о любви» переносится на 2 строки — закладки разной
  высоты; сыгранные плитки — пустые бледные контуры. Пластинки нет (её и не было, Б5).
- Окно отрывка: всё на месте, но таймер «4» без подписи, и под окном просвечивают плитки.

**Финал**
- Таблица 16 команд: кегль ячеек **9.2 px** на 1920, **7.1 px** на 1899×905, **6.4 px** на 1366
  (`.fin-table td`); колонка названий занимает треть ширины, баллы мелкие. Шапка — «Р1…Р8» без названий
  раундов (F12). Медали в ячейке места крошечные.

**reduced-motion (1920×1080, `reducedMotion: 'reduce'`)** — не гасятся:
`.neon-title` `p-unfurl 1.1s` (все лобби) и `glitchRGB 16s` (заставки раундов, ожидание ответов, финал —
киберпанковский глитч в Книге), `.p-ros-num` `p-flip 0.4s` (каждую секунду таймера), `.choice-plate`
`ruleIn 0.45s` (варианты), `.mel-modal` `p-grow 0.9s`. Вымпелы/QR гасятся (0.001s).

**Не про Книгу, но найдено стендом — баг в `src` локального режима бара**
- Предзагрузка треков «Угадай мелодию» на локальном сервере бьёт в
  `/api/media/api/media/book/mel-*.mp3` → 404 (видно в `measure.json → media`). `MelodyRound` передаёт в
  `preloadAudio` уже готовый адрес `mediaUrl(...)` = `/api/media/...`, `audioSource.pathFromUrl`
  узнаёт только облачный адрес Supabase, и `fetchMediaBlob` добавляет префикс второй раз. Следствие в
  баре: прогрев треков и запасной путь воспроизведения (через blob) не работают, пульт видит статус
  звука «ошибка»; прямой путь `el.src = '/api/media/…'` играет (на стенде трек реально зазвучал).
  `src/` в этом заходе не трогали — в бэклог (HANDOFF §7).
