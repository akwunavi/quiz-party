# Редактор компоновки — архитектура (прототип, не в боевой админке)

Статус: НА СОГЛАСОВАНИИ. Миграции БД нет; в игру и в боевую админку не подключён. Прототип: `review/layout-editor.html` (подложка — кадры экранов «вопрос»/«ответ»; перетаскивание, ресайз, авто/вручную, сброс — проверены в headless).

## 1. Как сохраняются настройки вопроса и ответа
Одно необязательное поле `layout` внутри JSON самого вопроса (в `pack_questions` уже есть jsonb-колонка со служебными полями вопроса — отдельной колонки/таблицы/миграции не нужно):

```
layout?: { question?: Rects, answer?: Rects }
Rects = { v: 1, text?: Rect, image?: Rect[] }      // Rect = { x, y, w, h } — ДОЛИ рабочей области 0…1
```
Для экрана вопроса и экрана ответа — два независимых блока. Хранятся только относительные значения (доли рабочей области страницы-разворота, без пикселей), поэтому одна и та же правка одинаково работает на 1280×720, 1920×1080 и 3840×2160.

## 2. Как обеспечена адаптивность
- Рабочая область — та же, что у `BookSafeArea` (`ny/book/adaptive/safeArea.ts`): между полями декора, ниже служебной полосы с таймером; доли пересчитываются в единицы сцены `--u`.
- Перед применением прямоугольники клампятся: внутри рабочей области, мин. размер 10 %, обход слота таймера; пересечения текста и картинки не допускаются (при пересечении побеждает авто-раскладка).
- Текст внутри ручного прямоугольника по-прежнему вписывается `useFitText` (только уменьшение, без `!important` на кегле).

## 3. Авто-компоновка по умолчанию
Если `layout` нет или он не проходит проверку — работает действующая адаптивная система (`mediaLayout`/`singleLayout`/`fit`: «текст», «текст + 1 картинка», «4 картинки», картинка ответа рядом с ответом и т. д.). Ручной режим — исключение, а не правило; авто остаётся единственным источником истины по умолчанию.

## 4. Как сбрасываются пользовательские правки
Кнопка «Сбросить» (и переключатель «Авто») удаляет блок `layout.question` или `layout.answer` целиком (а не обнуляет значения): вопрос мгновенно возвращается к авто-компоновке. Сброс одного экрана не трогает другой.

## 5. Поведение при отсутствии настроек
Поле отсутствует → авто. Поле битое/неизвестная версия `v` → игнорируется и тоже авто (проектор не падает и не показывает пустой экран). Старые пакеты без поля читаются как раньше.

## 6. Как предотвращается повреждение существующих данных квиза
- Поле только добавляется и никогда не переименовывает/удаляет существующие поля вопроса; пишется точечным merge-обновлением (`patch` одного ключа `layout`), а не перезаписью всей записи.
- Чтение — через общий нормализатор (проверка версии, диапазонов, типов), результат не мутирует исходный объект.
- Игровая логика, порядок показа, подсчёт очков и схема БД не затрагиваются; редактор не пишет в `game_sessions`/`answers`.
- Права записи — те же, что у редактора пакетов (`lib/packRights.ts`); в боевую админку не подключается до отдельного решения.
- Откат: удаление ключа `layout` в вопросе возвращает прежнее поведение полностью.

## Границы прототипа
Хранит правки в `localStorage` вкладки прототипа (не в БД), подложка — реальные кадры, а не живой проекторный компонент. Подключение к редактору и проектору — отдельный шаг после согласования.
