# Редактор компоновки — архитектура (прототип, не в боевой админке)

Статус: НА СОГЛАСОВАНИИ. Миграции БД нет; в игру не подключён.

## Идея
Ведущий для экрана вопроса/ответа с картинкой выбирает, как делить рабочую область между текстом и картинкой. Хранятся только ОТНОСИТЕЛЬНЫЕ значения (доли 0..1 рабочей области), поэтому раскладка не зависит от разрешения.

## Модель данных
```
LayoutOverride = { mode: 'auto' | 'manual', screen: 'question' | 'answer',
  imageRect?: {x,y,w,h}, textRect?: {x,y,w,h} }   // доли рабочей области
```
Хранение: поле `layout` внутри JSON вопроса (jsonb уже есть) — схема БД не меняется; чтение — `lib/questionFields`-стиль, без поля = auto.

## Поведение
- auto: существующая адаптивная система (`mediaLayout/singleLayout/fit`);
- manual: прямоугольники клампятся в рабочую область и обходят слот таймера;
- «сбросить» = удалить поле → auto; question и answer хранятся независимо;
- предпросмотр рисует реальный проекторный компонент (QuestionPreview), не копию.

## Границы
Прототип: `docs-dev/book-redesign/review/layout-editor.html` (подложка — реальные кадры экранов «Книги» вопрос/ответ, не живой компонент) — перетаскивание/ресайз прямоугольников в долях, переключение auto/manual, сброс, экран вопроса/ответа, сохранение только в localStorage прототипа. Подключение к редактору и проектору — отдельный шаг после согласования.
