# Bulldog №4 — проверка RUN и опорные кадры следующих анимаций

12 октября 2026. Анализ и производные файлы, без изменений существующих анимаций и игры.

## 1. RUN

Реальные файлы перепроверены. Две копии исходного `bulldog_4_run.mp4` имеют одинаковый SHA-256 `32e0f33959e726cf232bcf278129df9ccaa3f41280ceda064d5ecc4b7d0ea228`: H.264, 1276×720, 24 FPS, 121 кадр (#0–120). Утверждённый `dog4-run-alpha.webm` имеет SHA-256 `1a26ccd66ed780b75564a9fdb2fab5fc5cd0cd0b8b4d0e24e7d169d84fec045f`; его кадр alpha #n соответствует исходному #n+40.

Последняя согласованная игровая сборка использует START alpha #21–39, затем RUN alpha #0–10 (исходные RUN #40–50), затем циклически RUN alpha **#11–22** (исходные **#51–62**). В новых предпросмотрах цикл повторён **10 раз** без ускорения: 12 кадров = 0,5 с на повтор, 150 кадров / 6,25 с на весь ролик. Оба MP4 H.264/yuv420p/24 FPS/faststart, 1276×720 и 1920×1080; полностью воспроизведены Chromium до `ended`.

START #39 → RUN alpha #0 — соседние исходные кадры RUN #39→#40, промежуточных статичных кадров нет. RUN alpha #10→#11 также соседний переход источника #50→#51. На циклическом шве alpha #22→#11 передние лапы движутся немного назад и вверх, задние — вперёд и вниз, то есть в том же направлении, что при естественном продолжении #22→#23. Центр головы смещается примерно на 3 px влево и 4 px вниз; нижняя граница силуэта с y=686 на y=680 (естественный #22→#23: y=676). IoU alpha-силуэтов #22→#11 = 0,860, естественного #22→#23 = 0,807. Выраженного скачка размера, ракурса, корпуса или линии опоры в игровом масштабе не обнаружено. Эти измерения поддерживают выбор шва, но не подменяют художественную оценку походки. Сам цикл короткий, поэтому после многих повторов движение может восприниматься механически. Без новой оценки пользователя утверждать, что он идеален на проекторе, нельзя. Исходный RUN loop не изменялся, соседние альтернативы не подставлялись.

## 2. BASE_STAND и FINISH

`DOG4_BASE_STAND.png` — байт-в-байт копия существующего `stand-study/RUN_source_stand_00.png` (SHA-256 `b4588f89232be9181fb856cde572f87bb80d49bd86664a303d0d9be41e9eb659`). Это **именно RGB исходного RUN #0**, отделённый от исходного пола ранее подготовленной маской SNIFF #0 (совпадение силуэтов с маской RUN #0: IoU 0,996) и помещённый на непрозрачный нейтральный фон. Внутри силуэта цвет практически идентичен декодированному RUN #0; небольшие отличия возможны только на краю маттинга. 1276×720; собака смотрит вправо под тем же ракурсом ¾, все четыре лапы опираются, пропорции и положение не менялись. Полный исходный START начинается кадром RUN #0; сокращённый игровой монтаж использует START #21–39 из той же почти неподвижной начальной фазы. **`DOG4_FINISH_END.png` должен быть тем же самым файлом `DOG4_BASE_STAND.png`; отдельную копию не создавали.**

`DOG4_FINISH_START.png` — RUN alpha #22 = исходный RUN #62, наложенный без изменения геометрии на тот же нейтральный фон. Это конец реально используемого цикла и точка, после которой в текущей сборке начинается согласованный STOP. Собака ещё в фазе бега, передние лапы выставлены, задние частично подняты — пригодное исходное состояние для торможения.

Существующий STOP потенциально можно использовать как FINISH_DECELERATE: его первый кадр уже проверялся после RUN alpha #22, а последний кадр имеет IoU силуэта около **0,986** с маской исходного RUN #0, совпадающие границы опоры и центр. Но его действие создавалось для SNIFF_PEE; у крупного стыка RUN→STOP ранее отмечались небольшие изменения фазы лап и головы. Нужно отдельно визуально принять STOP в контексте пересечения финиша и проверить, что после него можно удерживать строго `DOG4_BASE_STAND` без заметной смены лица. Пока полноценный FINISH-клип не утверждён. Пара Start/End Frames даёт совместимые ракурс, окрас и фон, но между позами значительны движение корпуса и постановка лап; генерация по двум кадрам сама по себе не гарантирует естественные тормозящие шаги.

## 3. BUTTERFLY и BONE

| Действие | Вход и опорная поза | Возврат | Чего пока нет |
|---|---|---|---|
| BUTTERFLY | RUN alpha #22 → кандидат STOP → BASE_STAND; после остановки взгляд на отдельный игровой объект выше/впереди | Вернуться в BASE_STAND → существующий START #21–39 → RUN | Самостоятельный dog-only BUTTERFLY_ACTION; при несовпадении его конечной стойки — BUTTERFLY_RETURN. Нужно проверить, подходит ли один и тот же STOP по направлению головы. |
| BONE | RUN alpha #22 → кандидат STOP → BASE_STAND; после остановки внимание к отдельной косточке у земли | Вернуться в BASE_STAND → существующий START #21–39 → RUN | Самостоятельный dog-only BONE_ACTION; возможно отдельный BONE_RETURN, если собака заканчивает с опущенной головой. STOP нужно проверить в контексте реакции вниз. |

Ни бабочка, ни косточка не должны появляться внутри видео собаки; оба объекта привязываются к координатам дорожки. Для новых клипов требуются те же размер 1276×720, ракурс ¾ вправо, масштаб и линия опоры, начало/конец в BASE_STAND. Использование STOP для обоих действий — лишь кандидат, не автоматическое решение.

## 4. План полного прогона

`BASE_STAND [готов] → START [готов] → RUN [рабочий цикл] → STOP + SNIFF_PEE + RETURN + START [готовая рабочая сборка] → RUN → STOP? + BUTTERFLY/BONE_ACTION + RETURN? + START [действия и, возможно, возврат отсутствуют] → RUN → FINISH_DECELERATE? [кандидат STOP, не принят для финиша] → FINISH_STAND [BASE_STAND готов]`.

Перед полной сборкой проверить вход/выход новых действий и финишную остановку именно в масштабе гонки. Длинное SNIFF_PEE-событие уже занимает около 12,22 с со STOP/RETURN/START; второе длинное событие может создать затянутую паузу. Для будущей интеграции связать скорость продвижения с фазами торможения, неподвижного действия, возврата и разгона; не выводить прогресс или результат из часов видеоплеера. Race Scenario V2 и продолжительность гонки пока не изменялись.
