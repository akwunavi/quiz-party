### Точное соответствие исходного RUN и alpha RUN

Утверждённый alpha RUN содержит 81 кадр и соответствует диапазону исходника #40–120 включительно: alpha #n → source #n+40. Во всех 81 промежуточных RGBA-кадрах RGB непрозрачных пикселей побайтно равен соответствующему исходному кадру. В ранее сохранённой проверке Chromium шесть выборочных кадров имели прозрачный фон и непрозрачное тело в проверенных точках; это не доказывает качество матта на каждом пикселе каждого кадра. Извлечённые PNG исходного RUN названы с единичным смещением: `source/0041.png` содержит исходный кадр #40. Новая START-маска исходного RUN #0 и SNIFF-маска #0 имеют IoU 0,9977 при пороге alpha 50%, что подтверждает почти одинаковый входной силуэт; движение и выход этим числом не проверяются. Не считать RUN source #0 первым кадром утверждённого alpha RUN.

## 1. START: исходный RUN #0–40 → RUN

**Ответ:** частично готов: alpha START и связующий MP4 созданы, воспроизводимость технически проверена. Можно передавать кандидата на пользовательскую визуальную оценку; естественность при 1× и пригодность стыка не утверждены.

Нужно заполнить по видеоряду, не только по геометрии конечных кадров:

- Первый отмеченный признак движения/загрузки: source RUN #24.
- Лапы подаются вперёд: source #34–35; первый полёт отмечен на #36.
- Разгон Source #0–39 содержит загрузку #24, движение лап вперёд #34–35, первый полёт #36; устойчивое беговое движение затем продолжается в утверждённом RUN alpha.

## 2. STOP: возможность торможения из имеющегося RUN

**Ответ:** готового STOP из существующих кадров нет. Визуальная оценка диагностических кандидатов при 1× PENDING.

- В `03_stop_feasibility.mp4` показан RUN alpha #0–22 в обычном темпе, затем freeze кадра #22 на 8 кадров и hard cut на SNIFF #0 с удержанием. Это демонстрация отсутствующего STOP, не успешное торможение.
- Кадр alpha #22 / source RUN #62 имеет линию контакта около y=685 px, близко к STAND y=689 px; задние лапы при этом подняты, поэтому близкая линия пола не означает посадку в стойку. Alpha #28 / source #68 имеет лучший IoU, но корпус находится примерно на 41 px выше линии опоры.
- Обратный source RUN #39→#22 (около 0,75 с) — только кандидат для диагностики последовательности контактов. На 1× он не проверен, а длительность превышает V2 фазу замедления 0,5 с. Он не считается предложенным готовым STOP.
- Ни одна из этих проб не показывает подтверждённые перенос веса и естественное прекращение движения корпуса; требуется новое движение STOP.

Простой slow motion с последующим резким переходом в STAND не будет считаться готовым STOP. Если подходящего переноса веса нет, вывод должен прямо требовать новую анимацию STOP.

## 4. RETURN: SNIFF_PEE → STAND

**Ответ:** да, отдельное RETURN необходимо для возвращения в STAND в показанной последовательности; визуальное качество ролика при 1× PENDING.

- В `05_return_feasibility.mp4` показаны SNIFF #208–240, затем hard cut на SNIFF #0 (общая стойка). Между ними удерживается #0; это намеренная демонстрация несовместимых поз, а не сгенерированный RETURN.
- Размеченные кадры #216–234 остаются боковой стойкой, а #240 — шагом; естественное возвращение к начальному ракурсу в этих диапазонах не отмечено.
- Для референсной генерации выбран endpoint SNIFF #224 (устойчивая боковая стойка) → STAND #0; альтернативы #216, #234, #240 сохранены в contact sheet. Нужен отдельный RETURN-клип или переработка конца действия. Пригодность анимации при 1× остаётся непроверенной.

Ранее в `stand-study/REPORT.md` указано, что конец SNIFF имеет боковой ракурс, а #224 и #240 несовместимы с начальным STAND. В `transition-rework/REPORT.md` также описано несовпадение профиля SNIFF #240 и ракурса RUN #0. Эти наблюдения предварительны для текущего аудита и должны быть подтверждены на актуальных файлах.

## 6. Race Scenario V2 и длительность действия

**Кодовая проверка:** выполнена read-only в `quiz-party/src/lib/raceScenarioV2.ts:131-137`.

Актуальный код задаёт SNIFF_PEE длительностью 5,0 с: `decelerate = 0.5`, `stop = 0.3`, `accelerate = 0.6`, `act = duration - decelerate - stop - accelerate = 3.6`. Отдельного RETURN-интервала в событии нет. Временная модель берёт длительность события в расчёт состояния гонки, поэтому изменение её длительности затрагивает прогресс/финиш.

- Полный SNIFF #0–240: 241/24 = 10,0417 с. Диапазон #0–216 с нейтральной начальной и пост-подъёмной устойчивой конечной позой длится 217/24 = 9,0417 с, но заканчивается в боковом ракурсе.

## Итоговые выводы

### Что можно собрать из уже оплаченных материалов

- **START:** технически собран кандидат из исходного RUN #0–39 с последующим утверждённым alpha RUN. Подготовлены alpha WebM и H.264 MP4; прозрачность, совпадение RGB тела с исходником, выбранные фоновые пробы и браузерный playback проверены. Предложить пользователю оценить при 1×; до этого не утверждать естественность перехода.
- **RUN loop:** исходный шов alpha #80→#0 имеет IoU 0,512 и смещение центра. Внутренний участок alpha #3–13 с возможным швом #13→#3 выглядит перспективным техническим кандидатом, но не проверен при 1× и не заменяет утверждённый цикл.
- **SNIFF:** исходный полный клип и два среза доступны для сравнения. Проверенные кандидаты от приблизительно нейтрального #12 до устойчивого #216 занимают 8,542 с, а от точно общей стойки #0 — 9,042 с. Ни один не возвращает собаку в ракурс STAND.

### Какие движения отсутствуют и требуют новых анимаций

- **STOP:** готового переноса веса и постановки лап в доступном RUN не выявлено. Freeze и reverse-проба не создают подтверждённого торможения. Нужен отдельный STOP либо новый цельный клип с ним.
- **RETURN:** имеющийся SNIFF заканчивает в профильной стойке/шаге. Нужен отдельный RETURN из конечного поведения к общей STAND-позе либо новая версия SNIFF с таким концом.
- **START:** дополнительная генерация нужна только если пользователь отклонит готовый кандидат при визуальной оценке.

### Рекомендованный порядок последующих работ

1. Оценить `01_start_from_existing_run.mp4` и alpha WebM при 1× на целевом экране; принять или отклонить START.
2. Отдельно оценить `02_run_loop_test.mp4` и `02b_internal_loop_candidate.mp4`; оставить исходный RUN неизменённым до приёмки альтернативы.
3. Выбрать длительность SNIFF и согласовать её со сценарием. Полный клип с отдельными фазами V2 потребует примерно 11,44 с; изменение продолжительности события повлияет на финишное время.
4. Только после решений по длительности и endpoints заказывать STOP и RETURN или единый клип с совместимыми концами. Проверять каждый новый результат при 1× до следующей генерации.

### Риски, которые нельзя снять без новой генерации

- Натуральное торможение с постановкой лап и переносом веса.
- Возврат из бокового ракурса SNIFF в трёхчетвертной STAND без скачка головы, корпуса, размера и линии опоры.
- Совместить полное утверждённое поведение SNIFF (~10,04 с) с событием V2 в 5 с невозможно без сокращения/переопределения действия или согласованного изменения сценарной длительности. Изменение времени события влияет на результаты гонки.
- Качество движения при 1× на проекторе; технический декод и браузерный smoke-check не заменяют эту оценку.
