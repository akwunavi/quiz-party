# Bulldog №4: повторная диагностика RUN → SNIFF_PEE → RUN

Статус: **склейка не прошла визуальный критерий**. Предыдущий preview отклонён пользователем. Две новые монтажные версии ниже предназначены для сравнения и не выдаются за утверждённую анимацию.

- Прозрачный SNIFF_PEE v2: 241 кадр, 1276×720, 24 FPS. Содержание действия, включая язык и повторный подъём лапы, не изменялось.

Координаты ниже измерены по альфа-маске `A > 64` в кадре 1276×720. `bbox` — границы всего видимого силуэта; «центр» — центр массы альфа-маски, а не анатомический сустав. Для лап указаны горизонтальные интервалы нижней части силуэта (`y=620..699`); они показывают, какие контакты не совпадают. Это воспроизводимые измерения, а ракурс и позы оценены визуально по покадровым листам.

## Диагностика прежнего preview

Его монтажный скрипт переводил выходной кадр 59 (2,458 с) с RUN #60 на SNIFF #3 в выходном кадре 60 (2,500 с). Вторая склейка: SNIFF #240 в выходном кадре 297 → RUN #48 в выходном кадре 298 (12,417 с). Кадры реально извлечённого MP4 показаны в `previous_entry_eight_frames.jpg` и `previous_exit_eight_frames.jpg`. Входной RUN движется вперёд в фазе опоры одной передней лапы; следующий кадр SNIFF уже стоит на нескольких лапах. На выходе профильная стоящая голова с открытым глазом мгновенно становится головой RUN в ракурсе три четверти, причём RUN #48 закрывает глаза. Плавное наложение целых кадров даёт одновременно две морды, уши и наборы лап. Текущая задача не меняла старый MP4.

## Новые точки и геометрия

Обе версии используют **RUN #59 → SNIFF #12** и **SNIFF #240 → RUN #0**. Кадр #59 оставляет хотя бы одну переднюю лапу у земли; #12 сохраняет начальную стойку и удаляет только первые 0,5 с неподвижного вступления SNIFF. При выходе кадр RUN #0 с открытыми глазами лучше, чем прежний #48. Полезное SNIFF сохраняет кадры #12–240 включительно, то есть 229/24 = **9,542 с**. Движения нюхания, лапы и языка сохранены.

Преобразования производных кадров: входной RUN — 1,00× без внутреннего смещения; SNIFF — равномерно 0,87×, `x=+25`, `y=-4` относительно нижнего центра холста; выходной RUN — 1,00×, `x=+100`, `y=+15`. На фоне есть отдельная контактная тень. Оба RUN используют одни и те же утверждённые RGBA кадры, SNIFF — обработанные RGBA кадры. Изменение масштаба не раздельное по осям.

После этих преобразований, при одинаковом смещении персонажа по сцене на стыке:

| Стык | Кадр | bbox (x1,y1,x2,y2) | центр | нижние интервалы x |
| --- | --- | --- | --- | --- |
| вход до | RUN #59 | 388,105,940,689 | 693,412 | 588–719; 800–916 |
| вход после | SNIFF #12 | 458,109,899,689 | 709,415 | 458–514; 613–687; 767–843 |
| выход до | SNIFF #240 | 497,137,1025,691 | 766,435 | 511–594; 738–848 |
| выход после | RUN #0 | 522,142,994,691 | 758,428 | 524–576; 636–730; 828–920 |

**Вход:** вершина ушей и линия земли совпадают примерно в пределах 4 px; общий центр отличается на 16 px по горизонтали и 3 px по вертикали. Но ширина силуэта сжимается с 552 до 441 px (**20%**), а край морды перемещается назад на 41 px. Задняя лапа RUN висит позади; в SNIFF задняя лапа уже стоит и оказывается на 70 px правее заднего края RUN. Голова из движения вперёд немедленно переходит в неподвижный взгляд; ориентация морды меняется в кадре склейки. Попытка увеличить SNIFF до ширины RUN сделала бы рост и уши чрезмерно высокими и нарушила бы линию пола.

При отдельном измерении области туловища (`y=330..545`) её центр скачет с `(669,435)` на `(701,448)`, то есть на **32 px вправо и 13 px вниз**. Центр видимой области головы (`y=160..420`, `x>700`) смещается с `(808,312)` на `(791,302)`. Это объясняет, почему хорошее совпадение общего центра не означает совпадения частей тела. Силуэт RUN в последнюю секунду имеет выраженную фазу прыжка и посадки; первая секунда SNIFF — опора и наклон головы. В версии v1 горизонтальная скорость по сцене непосредственно перед стыком около 48 px/с и затем сразу ноль.

**Выход:** общий центр отличается на 8 px по горизонтали, 7 px по вертикали; верх силуэта на 5 px, нижняя точка совпадает. Ширина сокращается с 528 до 472 px (**11%**), край морды отступает на 31 px. Основной дефект — профиль SNIFF против ракурса три четверти RUN: меняется форма морды и видимость второго глаза. Передняя опорная лапа профиля превращается в две фронтальные лапы; опорный набор нельзя переставить равномерным сдвигом. Скорость туловища SNIFF в конце около нуля, RUN начинает следующий беговой цикл.

Измеренный центр туловища здесь `(757,442) → (754,436)`, но область головы перемещается с `(867,319)` на `(830,313)`, то есть **37 px влево**. Это визуально заметно как разворот и отступление морды, хотя корпус почти совпал. В версии v1 горизонтальная скорость по сцене меняется с нуля на ~47 px/с за один кадр.

## Попытка 1: монтаж и геометрия

`transition_v1_alignment.mp4`: 60 кадров RUN с нормальной скоростью, затем SNIFF #12–240, затем 36 кадров RUN с #0. 325 кадров, 13,542 с. Мировая позиция перемещается слева направо во время бега и стоит на месте во время действия. На границах используется прямой монтаж без crossfade. Геометрические размеры и линия земли стали стабильнее, чем в старом preview. Переход в стойку всё ещё скачкообразный, а на выходе резко меняется ракурс. **Критерий качества не достигнут.**

## Попытка 2: скорость лап и перемещения

`transition_v2_speed_ramp.mp4`: перед действием 65 кадров RUN, последние 0,55 с скорость источника линейно снижается примерно с 1,0 до 0,35. После действия RUN стартует с 0,35 и за 0,55 с разгоняется до 1,0. Смещение собаки по сцене интегрируется из **той же** функции скорости, поэтому перемещение по трассе и частота движения лап согласованы. SNIFF #12–240 остаётся при исходной скорости. Нет длительной заморозки или наложения целых видеослоёв. 330 кадров, 13,750 с. Торможение и разгон читаются лучше, но анатомический скачок на обоих стыках остаётся. **Критерий качества не достигнут.**

Скорость в этом варианте всё ещё делает остаточный скачок `0,35 → 0` на входе и `0 → 0,35` на выходе. Конечная скорость 0,35 — выбранный для этой пробы компромисс, **не** физическое ограничение 24 FPS: ramp можно довести до нуля, а квантование даст повторы некоторых кадров. Однако доступный RUN не содержит нужного переноса веса в стойку, поэтому одно изменение скорости не создаёт естественного STOP/START. Для этого нужно новое движение с промежуточными позами.

Позднейшее отдельное исследование общей стойки после просмотра всех фаз RUN выбрало кадр RUN #22 как более близкий к опоре референс для будущего STOP. В этой монтажной пробе использовался #59, чтобы сохранить выбранную временную точку в RUN; это разные эксперименты, и #22 не подменяет кадры уже экспортированных v1/v2.

## Попытка 3: интерполяция

Проверен доступный FFmpeg `minterpolate` с bidirectional motion estimation и overlapped block motion compensation на обоих парах совмещённых кадров. Результаты в `flow_entry_study.jpg` и `flow_exit_study.jpg`. В промежуточных кадрах видны удвоенные/прозрачные лапы, смазанная морда и лишние контуры ушей. Алгоритм не знает скрытых конечностей и не может правдоподобно повернуть голову из профиля в три четверти. Отдельный `transition_v3_interpolation.mp4` **не создан**, поскольку результат хуже прямой склейки. Новые модели и тяжёлые зависимости не добавлялись.

## Что чем исправляется

1. **Монтаж и геометрия:** общий центр, размер по высоте, линия земли, небольшая разница позиции морды и выбор более подходящей фазы RUN. Эти элементы улучшены в v1/v2.
2. **Требуется промежуточное движение:** перенос веса с передней опорной лапы на устойчивые четыре лапы, постепенное прекращение бегового цикла, обратный толчок задних лап, поворот головы, смена видимых/закрытых лап. Это полноценная локальная анимация, а не простая интерполяция двух картинок.
3. **Не получить из имеющихся исходников обычным монтажом:** достоверный поворот головы и корпуса между разными ракурсами с сохранением окраса и анатомии, а также отсутствующие позы торможения/отталкивания. Требуются два отдельных коротких переходных клипа.

## Техническое задание для двух переходных клипов

Четыре исходных endpoint PNG сохранены без изменения пропорций и исходного разрешения: `01_run_stop_frame_059.png`, `02_sniff_start_frame_012.png`, `03_sniff_end_frame_240.png`, `04_run_resume_frame_000.png`. Все PNG 1276×720, RGBA. В генераторе с поддержкой Start Frame / End Frame:

- **RUN → STOP:** Start Frame `01_run_stop_frame_059.png`, End Frame `02_sniff_start_frame_012.png`. Длительность целевого движения 0,7–1,0 с. Собака теряет скорость, ставит сначала переднюю, затем заднюю лапу, переносит вес и заканчивает точно в позе SNIFF #12. Камера и масштаб фиксированы. Не добавлять нюхание или поднятие задней лапы в мостик.
- **STOP → RUN:** Start Frame `03_sniff_end_frame_240.png`, End Frame `04_run_resume_frame_000.png`. Длительность 0,6–0,9 с. Из стойки перенос веса на задние лапы, затем естественный первый толчок и выход в позу RUN #0. Поворот корпуса/головы должен быть постепенным, уши и обе видимые передние лапы не должны удваиваться.

Для обоих: тот же сине-серый бульдог, 1276×720, 24 FPS, полный рост и все лапы внутри кадра, неподвижная камера, единая линия земли, без новых предметов/персонажей и без изменения выражения или окраса. Сохранять оба endpoint кадра точно либо предоставить последние 2–3 кадра, максимально близкие им. Если сервис не принимает прозрачные PNG, сделать копии на **одинаковом** нейтральном фоне без изменения масштаба и координат. Новые платные видео здесь не генерировались.

## Проверка и воспроизведение

В комплекте: отдельные MP4 v1/v2, последовательное сравнение `transition_comparison_v1_v2.mp4`, листы восьми соседних кадров обоих стыков, листы двухсекундных интервалов, оптическая проба и четыре endpoint PNG. MP4 имеют H.264, `yuv420p`, 1276×720, 24 FPS, `faststart`, без ненужной аудиодорожки. Их можно открыть двойным кликом в Windows. Сравнение идёт последовательно: сначала v1, затем v2; названия показаны на самих кадрах.

Покадровые листы и интервал ≥1 с до/после стыков проверены. Полная техническая декодировка MP4 выполнена. Непрерывное отображение в браузере в этой среде не подтверждено; эстетическое качество при 1× остаётся на оценку пользователя. Успешной склейка не объявляется.

Исходники, утверждённый RUN, обработанный SNIFF v2, предыдущая лаборатория, Race Scenario V2, Visual Pass 3 и production не изменялись. Merge и deploy не выполнялись.
