# Пупс (dog4) — интеграционный пакет 1.0.0 (02.11.2026)
Полный комплект утверждённых и рабочих анимаций собаки №4 «Пупс» для подключения к общему экрану выбора и к гоночной арене. Новых движений, генераций и «улучшений» нет: пакет только описывает и проверяет то, что уже принято. Собака №5 (работа Codex) сюда не относится.

## Как подключить к общему экрану выбора
1. Загрузить `IDLE` и `SELECTED` (WebM VP9 + alpha, пути — `MANIFEST.json → selection.states`). Нужен браузер с прозрачным VP9 (Chromium проверен). Для показа точного кадра — перемотка `currentTime = (кадр + 0,5) / 24`, как в лабораториях.
2. Рисовать оба клипа и G0 **одним** преобразованием: весь кадр 1276×720 вписать в карточку (эталон — 638×360).
3. **Компоновка карточки обязательна:** верхний край изображения = верхний край области карточки, содержимое за краем обрезается (`overflow: hidden`). На SELECTED s63–s70 кончики ушей выходят за верх кадра. При такой компоновке они уходят за край карточки, и это выглядит естественно. Если над кадром виден фон, будет виден ровный срез ушей. Растушёвку, уменьшение собаки и сдвиг кадров не применять (решение 02.11.2026).
4. Логика — `runtime/dog4_selection.mjs`:
   ```js
   import {createSelection} from './dog4_selection.mjs';
   const sel = createSelection(manifest.selection.policy.gates);   // IDLE с f0
   // каждые 1/24 с:
   const {clip, frame} = sel.next();   // 'IDLE' | 'SELECTED', номер кадра
   // игрок подтвердил выбор:
   sel.pick();                         // false, если уже ждём или идёт SELECTED
   ```
   IDLE доигрывает вперёд до ворот (не больше 3,625 с), SELECTED играет один раз целиком, затем IDLE с f1. Кроссфейда, паузы на G0 и клипа RETURN_TO_IDLE нет. Модуль сверен с утверждённой лабораторией `selection_v2` для выбора на каждом из 240 кадров IDLE — кадры и порядок совпадают (`results/selection_logic_check.json`).
5. Когда игра уходит с экрана выбора в гонку — это смена экрана. Клипа-моста нет и не требуется.

## Как подключить к гоночной арене (Race V3)
1. Физика — общая `dog4-v3-lab/model.mjs`, пакет её не меняет. Пупс — эталон, на котором V3 построен: его кадровый контракт `race-v3-p3-lab/characters/dog4.contract.json` тождествен `frameFor` (тест P3 T2 PASS, повторено 02.11).
2. Атлас: `dog4-v3-lab/manifest.json` + `dog4-v3-lab/assets/*.png` (ячейка 178×100, 24 в ряд). Тот же атлас побайтно — `race-v3-frenk-lab/dog4assets/`.
3. Рисование (`dog4-v3-lab/app.mjs`): `drawImage(ячейка, x − 148, laneY − 110, 207, 116)`, где x — позиция собаки на трассе, laneY — линия дорожки. Лапы стойки (строка 95 из 100 в ячейке, ×1,16 = 110,3) стоят на laneY.
4. События и клипы — `STATES_AND_TRANSITIONS.md`. Для SNIFF_PEE после действия идёт RETURN (клип атласа `return.png`); после BUTTERFLY и ROLL — сразу START.
5. **BUTTERFLY — только реакция собаки.** Летящую бабочку игра создаёт сама, отдельным объектом. В пакете собаки бабочки нет: из исходного видео она вырезана маской.
6. В общей гонке с собаками других форматов (у Фрэнка своя ячейка 207×116 и свои сдвиги) каждая собака подключается своим манифестом. Физика при этом одна.

## Что проверено (02.11.2026)
* 25 файлов манифеста — SHA-256 и размер совпали (местные и в ветках Codex).
* Экран выбора: IDLE 240 / SELECTED 121 кадр, VP9 + alpha, 1276×720, 24 к/с; G0 — PNG RGBA 1276×720. Якоря: s0, s120 и все 104 ворот совпадают с G0 (центр ≤ 0,2 px, лапы ±1 px).
* Гонка: 8 атласов — RGBA, сетка = число кадров, пустых ячеек нет, углы прозрачные; кадры = контракт V3 = диапазон `frameFor`; стоячие кадры на строке лап 94–95.
* `node dog4-v3-lab/validate.mjs` — без ошибок; тесты P3 (в копии): T1, T2, T3, T4, T8, T9, T10 — PASS. T5/T6/T7/T12 «частично/ошибка» и T11 «не запускался» относятся к старому контракту Фрэнка и к просмотру глазами — как в закоммиченном отчёте, к Пупсу не относятся.
* Два демо собраны только из файлов пакета. Смотрел их по кадрам, в реальном времени не смотрел.

## Известные допустимые ограничения (не дефекты, переделка не планируется)
1. **SELECTED s63–s70: кончики ушей за верхним краем кадра** (0,33 с, на пике подскока). Кадры не меняются; требование к карточке — см. выше.
2. SELECTED s64–s69: лапы в подскоке смазаны движением (так в исходнике); край смаза полупрозрачный, в игровом масштабе не читается.
3. Ожидание выбора до 3,625 с (выбор на f94, во время наклона головы); спокойные участки IDLE не сокращаются.
4. Атлас 178×100 рисуется в 207×116 (×1,163) — Пупс может выглядеть чуть мягче соседей. Решение 1.2 открыто, по умолчанию «как есть».
5. RUN: «полёт» нижней точки ≈ 11,8 px игры и скольжение лап ≈ 5 px/кадр относительно дорожки; цикл 0,5 с при долгом повторе может читаться механически. Это свойство утверждённого RUN, у Фрэнка того же класса.
6. STOP: «докатывание» опорных лап ≈ 20 px по дорожке (физика V3 ведёт спрайт при торможении); стык RUN → STOP крупно — смена фазы лап и головы (известно Codex).
7. START ускорен в начале (#0–23 втрое); ≈ 0,5 с стойки в конце ROLL; RETURN после SNIFF_PEE ускорен после замечания «топтание».
8. FINISH, RETURN, BUTTERFLY — «рабочие»: входят в эталон V3, отдельного «утверждаю» пользователя в документах нет.
9. Клипа-моста «анфас (экран выбора) → боковая стойка (гонка)» нет — смена экрана.
10. Синхронизация игровой бабочки с реакцией Пупса — по желанию: в исходном Kling бабочка видна ≈ #29–77.

**Блокирующих дефектов и отсутствующих обязательных клипов не найдено.** Несовместимостей контрактов нет: атлас, контракт V3 и `frameFor` сходятся покадрово.
