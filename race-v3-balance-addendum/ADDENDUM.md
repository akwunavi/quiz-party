# Дополнение к архитектуре P3: индивидуальные окна и компенсация времени

14.10.2026. Короткое дополнение, не новое исследование. Основа: P3-прототип `da8e623` (без изменений) и симуляции на реальной физике V3 (10 000 seeds, копия модели с переопределениями, оригиналы не тронуты; `prepare.sh`, `balance_sim.mjs`, `balance_results.json`). Production, Dog4, ассеты, `dog4-v3-lab` и `race-v3-p3-lab` не менялись; повторных тестов T1–T10 нет.

## 1. Что меняется в принципе

* Физические окна START, STOP и действий **могут быть индивидуальными**; канонические окна Dog4 — значения по умолчанию и контрольный эталон.
* Детерминизм: одинаковый результат при одинаковых **seed + составе + настройках**. Зависимость гонки (в т.ч. `effectiveSeed`) от состава допустима, но фиксируется: в симуляциях она проявляется в 5–15 гонках из 10 000.
* Визуальный слой P3 остаётся как есть: он читает сегменты и не знает, откуда взяты длительности. `lead`, `tail`, `pad` сохраняются как инструменты, но больше не обязательны.
* Принудительный retime не нужен: BUTTERFLY идёт в исходном темпе, ×1,0932 остаётся запасным.

## 2. Модель долга

Потерянное время относительно бега на крейсерской скорости: START — `START/2` на каждый старт, STOP — `STOP/2`, действие — вся длительность. **Долг события** = его потеря − потеря канонического события; положительный долг = персонаж проигрывает, отрицательный = выигрывает. Начальный START — отдельный долг.

| персонаж | начальный START | SNIFF | BUTTERFLY | ROLL |
|---|---|---|---|---|
| Френк «как снято» (START 31/24, STOP 73/24) | +0,146 | −0,752 | −0,271 | +0,896 (клипа нет, окно каноническое) |
| Френк, STOP = 63/24 (часть клипа с движением корпуса) | +0,146 | −0,960 | −0,479 | +0,688 |
| гипотетический «медленный» (START 1,3, STOP 2,2, действия +1,0 с) | +0,150 | +1,480 | +1,480 | +1,480 |

Долг зависит от числа и вида событий, которые случайны. Отсюда различие способов ниже.

## 3. Два способа компенсации

**M1. Постоянный коэффициент `k`.** Крейсерская скорость персонажа умножается на `k`; `k` подбирается так, чтобы среднее время финиша совпало с каноническим.

**M2. Компенсация потерянного на событиях времени с ограничениями.** Долг события гасится сразу после него:
* персонаж «впереди» (долг < 0) → **неподвижная пауза** в окне действия (точная, без изменения скорости, артефактов нет);
* персонаж «позади» (долг > 0) → **плавная добавка скорости** `m(t)=1+β·sin²(πt/W)` на следующих окнах RUN: нулевая в начале и конце (скачков нет), `β ≤ 8 %`, скорость меняется не быстрее `β·π/W ≤ 2 %/с`, окна короче 4 с не используются; непогашенный долг переносится дальше и в конце честно остаётся остатком.

Ёмкость M2 задана реальными окнами RUN после событий (46 000 окон): медиана 15,5 с → до 0,62 с долга; нижняя четверть 9,0 с → 0,26 с; 10,7 % окон короче 4 с вообще не работают. Переносимый долг накапливается по окнам.

## 4. Влияние на гонки с 0, 1 и несколькими событиями

Среднее смещение финиша персонажа относительно канонической гонки того же seed, с (чем ближе к 0, тем лучше). Гонки с 0 событий в сценарии V3 не возникают (минимум одно), поэтому они посчитаны на одиночной собаке; 1/2/3+ — на 10 000 реальных гонок (7 037 / 1 987 / 971 для Френка).

**Френк «как снято»** (долги малы и разного знака):

| событий | без компенсации | M1 (k = 1,0009) | M2 |
|---|---|---|---|
| 0 | +0,146 | +0,110 | **0** |
| 1 | +0,079 | +0,038 | +0,084 |
| 2 | −0,033 | −0,063 | +0,164 |
| 3+ | −0,132 | −0,166 | +0,346 |
| Δ шансов полосы, пп | −0,22 | −0,02 | −0,26 |
| смена победителя, гонок | 353 | 341 | **155** |
| разброс смещения (SD), с | 1,27 | 1,26 | **0,98** |

**Гипотетический «медленный»** (долг +1,5 с на событие, показывает границы способов):

| событий | без компенсации | M1 (k = 1,052) | M2 |
|---|---|---|---|
| 0 | +0,15 | **−1,92** | **0** |
| 1 | +1,59 | **−0,54** | +0,75 |
| 2 | +3,00 | +0,84 | +1,80 |
| 3+ | +4,30 | **+2,19** | +3,04 |
| Δ шансов полосы, пп | −6,71 | **+2,56** | −3,48 |
| смена победителя, гонок | 700 | 344 | 400 |

Что из этого следует:
1. **M1 выравнивает только среднее.** Остаток зависит от числа событий: для «медленного» персонажа в гонках с 0–1 событием он быстрее эталона, с 3+ — медленнее (−0,54 → +2,19 с); на 0 событий k даёт −1,9 с. Для Френка k ≈ 1,0009 ничего не меняет по гонкам (смен победителя 341 против 353). Знак эффекта на шансы переворачивается (−6,7 → +2,6 пп), то есть перекомпенсация.
2. **M2 точен там, где долг погашаем:** 0 событий — ровно 0; у Френка смен победителя вдвое меньше (155 против 353) и разброс ниже. Остаток у Френка (+0,08…+0,35 с) — непогашенные долги события ROLL (клипа нет), p95 остатка 0,9 с.
3. **У M2 есть потолок.** Для «медленного» персонажа долг 1,5 с на событие не гасится (остаток в среднем 1,2 с, шансы −3,5 пп): способ не должен заменять подгонку окон под бюджет долга.
4. Френк при STOP = 63/24 ведёт себя так же (в `balance_results.json`): долг STOP падает с 0,75 до 0,54 с на событие.

## 5. Совпадение STOP не решается коэффициентом

`k` меняет только крейсерскую скорость. Расхождение STOP — это (а) лапы клипа идут назад со скоростью ≈ 13 px/кадр против хода якоря 1,16 px/кадр, то есть для совпадения нужен `k ≈ 11`; (б) клип несёт ≈ 129 px перемещения при остановке, физика V3 даёт 21,5 px (STOP = 37/24), 36,6 px (63/24) или 42,4 px (73/24). Выбор `STOP_s` меняет только **время** остановки и её цену в долге (0 / 0,54 / 0,75 с на событие); скольжение лап остаётся свойством клипа и скорости трассы. Поэтому порядок такой: сначала визуальная оценка на трассе при трёх вариантах `STOP_s` (37/24 + `tail`, 63/24, 73/24), и только затем выбор числа; цену выбранного числа берёт на себя M2.

## 6. Рекомендация

**Принять M2 как механизм балансировки:** пауза в неподвижном окне при отрицательном долге, ограниченная добавка скорости при положительном, остаток фиксируется и входит в приёмку.
* `k` не использовать для балансировки: оставить как ручную ручку темпа (по умолчанию 1,0) и, при необходимости, как грубую подстройку **среднего остатка**, который M2 не смог погасить (после того как бюджет долга исчерпан).
* Бюджет долга при приёмке ассетов: положительный долг события ≲ 0,3 с гарантированно гасится (нижняя четверть окон), ≲ 0,6 с — в большинстве гонок. Френк по этому бюджету укладывается кроме события ROLL при длинном STOP — это задача при создании клипа ROLL (достаточно, чтобы клип + STOP + START укладывались в канонический расход времени или в бюджет).
* Критерий статистической приёмки (на 10 000 seeds, как здесь): среднее смещение по каждой страте (0/1/2/3+) ≤ 0,15 с, p95 непогашенного долга ≤ 0,5 с, `|Δ шансов|` ≤ 0,6 пп (≈ 1,5 SE), смен победителя меньше, чем у варианта без компенсации.

## 7. Минимальная схема метаданных

Добавляется к существующему контракту `character-visual-contract/v1-lab` двумя необязательными секциями; `clips`, `windows`, `keys`, `shift`, `limits` не меняются. Нет секции — канонические окна (Dog4 как есть).

```json
"physical": {
  "START_s": 1.2917,
  "STOP_s": 3.0417,
  "actions_s": {"BUTTERFLY": 3.875, "SNIFF_PEE": 8.333, "ROLL": null},
  "RUN_JOIN_s": null
},
"balance": {
  "mode": "debtRepay",
  "speedCoeff": 1.0,
  "debtRepay": {"betaMax": 0.08, "rMaxPerS": 0.02, "minWindow_s": 4, "holdWhenAhead": true, "debtBudget_s": 0.3}
}
```
`null` = клипа нет (явный пробел, а не канонический «как будто есть»); `mode`: `none` | `speedCoeff` | `debtRepay`.

## 8. Изменения для следующего этапа

1. **Лаборатория P3 (минимально, без переписывания):** `canonical.mjs` — `physicalFor(contract)` (по умолчанию канон); валидатор — окна и `lead` берутся из `physicalFor`, долг на событие считается и сверяется с `debtBudget_s`, пауза допустима только если клип короче окна; `visualAt` не меняется (читает готовые сегменты).
2. **Физический адаптер** в новой лаборатории-преемнике, не в `dog4-v3-lab`: сегменты собаки строятся из `physical`, пауза в окне действия, добавка скорости на RUN интегрируется аналитически; `crossing` остаётся аналитическим; seed-fallback видит состав и настройки.
3. **Проверки:** (а) физическая эквивалентность модели долга и честной интеграции добавки (здесь использована приближённая модель «кредит времени», ошибка ≤ 2 % кредита из-за вариации ±2 % по четвертям — проверить интегрированием); (б) Dog4 без секции `physical` бит-в-бит как сейчас; (в) пересчёт ограничений сценария (разделение 8 %, «не все стоят», порог `early`) с учётом пауз; (г) статистический критерий из раздела 6 на 10 000 seeds и на 0/1/2/3+ событиях; (д) T1–T10 повторить только после изменения физики.
4. **Ассеты:** визуальная оценка STOP Френка на трассе при трёх `STOP_s`; ROLL, alpha SNIFF_PEE и FINISH остаются открытыми задачами.

## 9. Ограничения этого анализа

Добавка скорости смоделирована как кредит времени (без интегрирования); пауза не пересчитывалась в ограничениях сценария; «медленный» персонаж гипотетический; окно ROLL Френка каноническое (клипа нет); подгонка `k` сделана на тех же 10 000 seeds (оптимистично для M1); визуальное восприятие добавки скорости на трассе не оценивалось.
