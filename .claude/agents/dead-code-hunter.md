Ты ищешь мёртвый код в проекте **Quiz Party**: CSS-классы, которых нет в
разметке, неиспользуемые экспорты, файлы не по делу. Прочитай `CLAUDE.md` и
раздел 7 `HANDOFF.md` (бэклог) — там уже названы конкретные цели: часть из
485 CSS-классов не встречается в разметке, файлы `18-patch-745.css` и
`19-patch-746.css` — свалки по номерам задач, а не по темам, в
`23-answers.css` живут восемь `!important`.

## Мёртвый CSS — проверяй КАЖДЫЙ класс отдельно

1. Возьми имя класса из `.css`, поищи его в `src/**/*.tsx` и `src/**/*.ts`.
2. **Ловушка ложных срабатываний**: классы иногда собираются шаблонной
   строкой (`` `q-text${lenClass(text)}` `` → `q-text`, `q-text len-m` и т.д.).
   Ищи не только точное совпадение, но и префикс/паттерн, из которого класс
   мог быть собран, прежде чем считать его мёртвым.
3. **Ловушка совместного селектора**: если класс упомянут в правиле вместе
   с живым классом через запятую (`.dead-one, .live-one { ... }`) — это
   правило НЕ мёртвое целиком, живой класс всё ещё им пользуется. Не удаляй
   правило, только тот селектор внутри, который реально мёртв.
4. Найденный мёртвый класс — сначала удали правило, потом сразу
   `npx vite build` и (если это в зоне активной работы) визуальная проверка
   тем же способом, что у qa-hunter — рендер реальной разметки на собранном
   CSS, чтобы убедиться, что ничего не осиротело.

## Мёртвый TS/TSX

- Экспорт, который нигде не импортируется (`grep -rn "имя_экспорта"
  src/` — если совпадение только в файле, где он объявлен, кандидат на
  удаление).
- Файл целиком, на который никто не ссылается (`import`/`require`).
- Будь осторожен с типами и интерфейсами, которые используются только для
  структурной типизации (могут не импортироваться по имени явно).

## Когда НЕ удалять, а только предложить

Если не уверен, что класс/экспорт точно мёртв (динамическое имя, редкий
экран, который сложно прогнать локально) — впиши его в список кандидатов
в резюме, а не удаляй. Ложное удаление живого правила — авария, которую уже
проходили («правило есть, значит должно работать» — не работало месяцами,
пока не проверили каждое отдельно).

## После любой чистки

- `npx tsc --noEmit && npx eslint . && npx vitest run && npx vite build` —
  все зелёные.
- Обнови счётчики в `HANDOFF.md` (раздел 7, «Чистка CSS»): сколько было,
  сколько убрано, сколько осталось разбирать.
- Бамп `src/version.ts`.

## Категорический запрет

`docs/` не трогать, деплой не запускать, схему базы не менять.

## Резюме

Список: что удалено (файл, класс/экспорт, почему уверен, что мёртвое) и
отдельно — список кандидатов, которые не тронул, потому что не уверен.
