# Архив Bulldog Race

Это точка входа в архив изолированной разработки Bulldog Race. Архив содержит реестр каждого обнаруженного файла, ссылки на существующие Git blobs и набор tar-частей для материалов, которые до этой задачи жили только во временной среде. **Архив отражает доступные источники, а не полную недоступную историю переписки.**

Начните с [RECOVERY.md](RECOVERY.md). Затем прочитайте [правила](APPROVED_RULES.md), [архитектуру V3](ARCHITECTURE.md), [решения](DECISIONS.md), [неудачные эксперименты](FAILED_EXPERIMENTS.md) и [реестр](ASSET_MANIFEST.json). Для каждого файла реестр содержит происхождение, SHA-256 и точный способ восстановления. `UNKNOWN` означает отсутствие доказанной приёмки, а не плохое качество.

Рабочая лаборатория V3 находится в `dog4-v3-lab/` этой ветки. Она использует пять визуальных копий Bulldog №4; другие собаки пока не интегрированы. Утверждённые исходники и production-код не изменялись при архивировании.

Архивные части `archive/parts/part-XXX.tar` хранят файлы по SHA-256. Исходные имена и пути не теряются: они находятся в записях `ASSET_MANIFEST.json`. Файлы, уже присутствующие в Git, повторно в tar не клались; реестр указывает ветку, commit и путь. Для промежуточных кадров это существенно уменьшает объём, сохраняя каждую логическую запись.

Основные документы: [история](PROJECT_HISTORY.md), [контракт анимаций](ANIMATION_CONTRACT.md), [ассеты №4](DOG4_ASSETS.md), [промпты](PROMPT_ARCHIVE.md), [alpha-конвейер](ALPHA_PIPELINE_NOTES.md), [известные проблемы](KNOWN_ISSUES.md), [следующие шаги](NEXT_STEPS.md).

Реестр построен инструментами `tools/build_archive.py` и `tools/annotate_manifest.py`. Первый собирает доступные локальные материалы и исторические Git blobs; второй добавляет статусы только при наличии доказательств и проверяет alpha декодированием. Для повторной проверки имеющегося архива служит `tools/verify_archive.py`. Повторная сборка требует исходной рабочей среды; восстановление из чистого клона использует уже сохранённые части и не требует её.
