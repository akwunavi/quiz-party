# CLAUDE.md — инструктаж для Claude Code

Этот файл читается автоматически в начале каждой сессии. Он не описывает
архитектуру «вообще» — он про то, как здесь принято работать и на чём тут
уже обжигались. Подробности живут в `HANDOFF.md`; **прочитай его целиком
перед первой правкой** — там разбор каждой ловушки.

Правило про сам файл: тот, кто вносит изменение, обновляет `HANDOFF.md` в
том же коммите. Устаревшая память хуже отсутствующей — ей верят.

---

## 1. Что это

Живая викторина для вечеринок в баре. Ведущий — один человек, он же
разработчик, тестировщик и автор вопросов. Играют команды: с телефонов
(`play_mode: online`) или на бумаге (`paper`).

Одновременно работают четыре поверхности:

- **Проектор** (`src/pages/HostScreen.tsx`) — то, что видит зал;
- **Админка** (`src/pages/AdminPage.tsx`) — пульт ведущего с телефона;
- **Телефон игрока** (`src/pages/PlayerPage.tsx`) — приём ответов;
- **Редактор** (`src/pages/editor/*`) — подготовка пакетов между играми.

Ошибка здесь стоит не «упавшего теста», а испорченного вечера у полного
бара людей, причём чинить некому: ведущий в этот момент стоит с
микрофоном. Отсюда весь тон этого файла.

## 2. Стек

React + TypeScript + Vite, Supabase (**только REST-поллинг, без
вебсокетов** — их режут мобильные операторы у части гостей), GitHub Pages,
тесты на Vitest.

Ключевые модули:

| файл | за что отвечает |
|---|---|
| `lib/totals.ts` | подсчёт баллов, ветка на КАЖДУЮ механику |
| `lib/scoring.ts` | формулы очков |
| `lib/flow.ts` | маршрут после раунда (табло, перерыв, финал) |
| `lib/blitz.ts` + `blitzState.ts` + `blitzApi.ts` | блиц целиком |
| `lib/answerQueue.ts` | очередь ответов с ретраями |
| `lib/ratings.ts` | оценки вопросов командами |
| `lib/devSeed.ts` | режим репетиции (`?dev=1`) и сверка начислений |
| `lib/jeopardyRef.ts` | ключ ответа на плитку «Своей игры» (оба формата) |
| `lib/media.ts` | `mediaUrl` и `lenClass` — общие для всех экранов |
| `lib/questionFields.ts` | какие поля вопроса показывать для механики |
| `components/Hint.tsx` | подсказки при ошибочных действиях (не блокируют) |
| `styles/parts/*.css` | 27 частей, порядок задан в `global.css` |

Механики раундов: `standard`, `test_stop`, `rebus`, `jeopardy`,
`stakes_unique`, `stakes_free`, `thematic_x2`, `crossword`, `sprint`,
`melody`, `race`, `blitz`.

## 3. Чего делать НЕЛЬЗЯ

Это не стилистические пожелания. Каждый пункт — уже случившаяся авария.

**Не трогай папку `docs/`.** Это прод: GitHub Pages раздаёт её и больше
ничего. Она пересобирается только скриптом деплоя. В облачной виртуалке
нет секретов `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` — они
вшиваются в бандл на этапе сборки из настроек репозитория. Значит любой
собранный тобой бандл, попавший в `docs/`, **положит живой сайт**:
приложение соберётся, но не найдёт базу.

**Не запускай `deploy.sh` и не пытайся деплоить.** Деплой делает человек
кнопкой Actions → deploy → Run workflow. Твоя работа заканчивается на
ветке с изменениями.

**Не делай `git reset --hard`, `git checkout .`, `git clean -fd` и
`push --force`.** Незакоммиченные правки этим уже уничтожались
несколько раз, и каждый раз это была работа за вечер.

**Не меняй схему базы сам.** Миграции складывай файлом в
`supabase/migrations/` и **словами скажи, что его надо прогнать вручную**
в SQL Editor. Автоматические попытки записи в эту базу не проходят
подтверждение и молча не применяются — потом выясняется, что таблицы нет,
а код на неё рассчитывает.

**Не изобретай данные.** Есть доступ к репозиторию — читай код, а не
угадывай. «Скорее всего, там так» здесь стоит дороже, чем лишние пять
минут на чтение.

**Не откладывай на потом то, о чём попросили.** Если задача звучит как
«почини четыре вещи» — чинятся все четыре. Промежуточные «а хотите, я
ещё добавлю?» не нужны: делай полностью, потом рассказывай, что сделал.

## 4. Что делать ОБЯЗАТЕЛЬНО

**Бампай `src/version.ts` в каждой правке.** Номер виден в углу экранов.
Если после деплоя там старая цифра — файлы не доехали, и обсуждать
правки рано.

**Перед тем как сказать «готово», прогони всё четыре:**

```
npx tsc --noEmit
npx eslint .
npx vitest run
npx vite build
```

Тесты проверяй не только по цвету, но и **по числу**: сейчас должно быть
**184 теста в 22 файлах**, меньше — что-то отвалилось. Раньше vitest брал
только файлы вида `*.test.ts`, и файл, названный `totals-melody_test.ts`,
молча не запускался; с 8.38 маска в `vite.config.ts` шире и такую опечатку
подхватывает.

Линтер (`npx eslint .`) узкий и заведён ради одного правила: хук после
раннего `return` — это падение React #310, которого не видят ни типы, ни
тесты. Красный он только на ошибках; тридцать предупреждений про зависимости
эффектов — осознанные.

**Обновляй `HANDOFF.md`** в том же коммите: новые ловушки — в раздел
ловушек, отложенное — в бэклог (раздел 7).

**Оформление новых компонентов — твоя работа по умолчанию.** Ховеры,
анимации, поддержка всех тем. Напоминать об этом не будут.

**Ошибку пользователя объясняй, а не блокируй.** Серая кнопка молчит и
оставляет человека гадать — вместо неё живая кнопка с подсказкой
(`useHint` из `components/Hint.tsx`), которая говорит, чего не хватает, и
ставит курсор в нужное поле. Подробности — `HANDOFF.md`, раздел 3d.

**Все цвета — через переменные:** `var(--accent)`, `var(--accent2)`,
`var(--glow)`. Хардкод цвета ломает темы.

**Кнопки навигации ведущего — только в `.host-actions`** (фиксированная
позиция: справа 28px, снизу 24px).

## 5. Ловушки, стоившие отдельного разбора

**Правило под несуществующий класс выглядит рабочим.** Стили писались под
`.answers-screen`, `.scoreboard-screen`, `.title-anim`, `.wind-text` —
таких классов в разметке нет, правила лежали месяцами и не делали ничего.
**Проверь класс в JSX, прежде чем писать селектор.**

**Порядок файлов важнее темы.** При равной специфичности побеждает файл,
который ниже в `global.css`. Тема (14) грузится раньше патчей (18, 19) и
экранов (22–28), её правила проигрывают. Не переставляй импорты «для
порядка» — поднимай вес селектора.

**Контекст наложения.** Правило в `15-projector-interactive.css` задаёт
`position: relative` всем прямым детям `.grid-bg`. Любой элемент со своим
`position` ОБЯЗАН стоять в списке `:not()`. Уже попадались шапка, номер
раунда, QR, `audio-gate`, модалка составов.

**Ширины в `vw` внутри контейнера с отступами.** `vw` — доля окна, а не
родителя. При отступах 44px сетка на 97vw вылезала за экран на 47px.
Внутри `.host-screen` ширины задавать в процентах.

**`play()` асинхронный.** `pause()` до его старта не делает ничего — звук
всё равно заиграет. Из-за этого звучала озвучка чужого вопроса. Правильно:
`v.play().then(() => { if (cancelled) { v.pause(); v.src = '' } })`.

**Хуки только до ранних `return`.** Хук после `if (...) return` даёт
падение React #310, видное только в рантайме: ни типы, ни тесты не ловят.
С 8.38 это ловит линтер — он же нашёл два живых случая (форма ответов на
телефоне и доска мелодии на проекторе).

**Экраны грузятся отдельными файлами** (`React.lazy` в `App.tsx`). Общую
мелочь клади в `lib/`, а не экспортируй из `HostScreen.tsx`: импорт оттуда
утаскивает весь проектор в чужой чанк. Подробности — `HANDOFF.md`, раздел 1a.

**Позиции не идут подряд.** `position` у раундов и вопросов — не индекс
массива. Новую считать как максимум + 1 запросом к таблице.

**Новая механика — это пять подключений**, а не одно: тип, проектор,
админка, телефон, подсчёт. Блиц был написан целиком и не работал, потому
что в `HostScreen` не было ветки.

**Итоги пишет тот, кто ведёт раунд.** Когда управление блицем переехало
на проектор, запись результатов осталась в админке — в зачёт летели нули.

**Очередь ответов не годится для пакетной записи.** Она читает список из
`localStorage` и пишет обратно; три параллельных вызова хватают один
снимок, выживает последний. Итоги блица так теряли две команды из трёх.
Пачку пиши одним `upsert`.

**Правя `computeTotals`, правь `computeRoundScores`** — иначе строка на
табло не сходится сама с собой.

**Сверка должна быть независимой.** Формулу для проверки писать по
правилам словами, а не срисовывать с кода подсчёта, иначе она сравнивает
код сам с собой.

**Медиа из репозитория кладётся в `public/`, а не в `docs/`.** `docs/`
пересобирается при каждом деплое, файл оттуда исчезнет.

## 6. Вёрстка

Юнит-тесты наложений не ловят. Проверка — рендер **настоящей** разметки
(с той же вложенностью, что в JSX) на собранном CSS в headless-браузере с
замером координат: пересекаются ли рамки, не уехал ли контент под кнопки
или под таймер. Модалка, вынесенная в стенде за `.host-screen`, вела себя
правильно и тем самым спрятала баг.

Проверять **по всем трём темам** (классика/киберпанк, Гарри Поттер,
Новый год) и **в обоих режимах игры**: у `paper` своя вёрстка — нет
колонки ответов, нет QR, у лобби свои размеры.

Если браузера в сессии нет — так и скажи. Не пиши «проверено», если
проверял только типами: на это здесь смотрят пристально.

## 7. Как отвечать

Ведущий — не программист по образованию и говорит об этом прямо. Значит:

- новые термины и любые команды в терминале объясняй словами, что они
  делают и что будет, если пойдёт не так;
- пиши по-русски, коротко, без канцелярита и без списков там, где хватает
  двух фраз;
- он общается прямо, включая мат при усталости. Это не требует извинений
  — это требует точной работы;
- когда ошибся — скажи, что именно сломал и как чинишь. Без
  самобичевания, но и без замалчивания;
- не обещай того, чего не сделал. Невыполненные обещания и непроверенная
  упаковка здесь замечаются сразу.
